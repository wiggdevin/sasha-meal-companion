# Lane O — Search recall: Implementation Plan (wave 3, Phase 1 AC8 unblock)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Sasha types "canned albacore", "eggs" or "chkn brst" and the right USDA row is in the list. The Phase 1
relevance gate (AC8) is blocked at top-1 42.6 % / top-3 77.1 % for two reasons named in `docs/catalog/relevance.md`
— candidate **recall** (the right row never reaches the scorer) and **no vocabulary layer** ("albacore" is USDA's
"tuna, white"). This lane fixes both **without touching the architecture §4.1 score**: a curated synonym table
expands the query before `websearch_to_tsquery` sees it, and the candidate where-clause gains a word-similarity
branch. `catalog_search`'s signature, its return columns and its score expression stay byte-identical, so Lane K,
Lane M and `lib/server/catalog.ts` read it unchanged.

**Architecture:** One migration adds `catalog_synonyms` (term → expansion, select-only for `authenticated`) and a
pure SQL helper `catalog_expand_query(p_q text) returns text` that lowercases, unaccents, splits on whitespace and
replaces each matched term with its expansion. `catalog_search` is re-created with the same signature: `tsq` is now
built from the expanded string, and the candidate set is `search_doc @@ tsq OR similarity(description, raw) > 0.25
OR word_similarity(raw, description) > 0.45` — `raw` stays the **original** query, which is what keeps `f_trigram`
and therefore the score unchanged. `docs/catalog/synonyms.csv` is the source of truth for the table's rows;
`scripts/load-synonyms.ts` makes the table equal the file. `lib/search/query.ts` gains `expandQuery(q, synonyms)`,
a TypeScript mirror of the SQL helper used only by the parity test. Then the eval re-runs on the branch and
`docs/catalog/relevance.md` gains a dated re-measurement section; contracts §7's gate rule decides landing.

**Tech Stack:** Next.js 16.3.4, React 19, TypeScript, Tailwind 4 (DESIGN.md tokens only), pnpm 11, Node 22,
vitest 5 (node environment), Supabase Postgres 17 (`pg_trgm`, `unaccent`), `tsx` for scripts. No new npm
dependencies. No UI in this lane.

```ts
/**
 * The TypeScript mirror of SQL `catalog_expand_query` (migration 20260921090000).
 *
 * The API route never calls this: `app/api/foods/search/route.ts` passes the raw query and the
 * SQL helper does the expansion inside `catalog_search`, so there is no `loadSynonyms` on the
 * client and the browser bundle never carries the table. This mirror exists for the feature
 * parity tests — `tests/search/recall.test.ts` asserts SQL and TypeScript agree on the same
 * strings, and `tests/search/score-parity.test.ts` keeps reading the SQL's own seven feature
 * columns, which are computed from the UNEXPANDED query and are therefore unaffected.
 *
 * Matching is two-word-first, then single-token, and each token is consumed once: an expansion is
 * never re-expanded, so the table cannot cycle.
 */
export function expandQuery(q: string, synonyms: Map<string, string>): string {
  const tokens = (q ?? "")
    .normalize("NFD")
    .replace(/[̀-ͯ]/g, "")
    .toLowerCase()
    .trim()
    .split(/\s+/)
    .filter((t) => t.length > 0);
  const out: string[] = [];
  let i = 0;
  while (i < tokens.length) {
    const pair = i + 1 < tokens.length ? synonyms.get(`${tokens[i]} ${tokens[i + 1]}`) : undefined;
    if (pair !== undefined) {
      out.push(pair);
      i += 2;
      continue;
    }
    out.push(synonyms.get(tokens[i]) ?? tokens[i]);
    i += 1;
  }
  return out.join(" ");
}
```

```sql
-- The vocabulary layer. Lowercase, unaccent, split on whitespace, then replace: a two-word term
-- first, a single token otherwise. Each token is consumed once, so an expansion is never expanded
-- a second time and the table cannot cycle. lib/search/query.ts's expandQuery() is the same
-- algorithm in TypeScript and tests/search/recall.test.ts holds the two together.
--
-- Two-word terms are not a flourish: docs/catalog/synonyms.csv needs 'duck fat' and
-- 'pumpkin puree', and it needs 'egg whites' to fire before the 'egg' row does, or the query
-- "egg whites" would expand to "egg whole whites" and lose its own target under the AND that
-- websearch_to_tsquery applies.
create or replace function public.catalog_expand_query(p_q text)
returns text
language plpgsql
stable
security invoker
set search_path = public, extensions, pg_temp
as $$
declare
  toks      text[];
  out_parts text[] := '{}';
  n         integer;
  i         integer := 1;
  hit       text;
begin
  toks := array_remove(
            regexp_split_to_array(btrim(lower(unaccent(coalesce(p_q, '')))), '\s+'),
            '');
  n := coalesce(array_length(toks, 1), 0);
  while i <= n loop
    hit := null;
    if i < n then
      select s.expansion into hit
        from public.catalog_synonyms s
       where s.term = toks[i] || ' ' || toks[i + 1];
    end if;
    if hit is not null then
      out_parts := out_parts || hit;
      i := i + 2;
    else
      select s.expansion into hit
        from public.catalog_synonyms s
       where s.term = toks[i];
      out_parts := out_parts || coalesce(hit, toks[i]);
      i := i + 1;
    end if;
  end loop;
  return btrim(array_to_string(out_parts, ' '));
end;
$$;

revoke execute on function public.catalog_expand_query(text) from public, anon;
grant  execute on function public.catalog_expand_query(text) to authenticated, service_role;

comment on function public.catalog_expand_query(text) is
  'Expands a search query through catalog_synonyms (contracts §7). Mirrored by expandQuery() in lib/search/query.ts.';
```

```sql
-- function carried before this migration and carries after it, byte for byte:
--

  catalog_food_id bigint,
  revision_id bigint,
  description text,
  brand text,
  source text,
  quality_class text,
  quality_flags text[],
  prep_state text,
  score numeric,
  pref_status text,
  f_lexical numeric,
  f_trigram numeric,
  f_brand numeric,
  f_prep numeric,
  f_prior numeric,
  f_quality numeric,
  f_eats numeric
)
language sql
stable
security invoker
set search_path = public, extensions, pg_temp

as $$

    select
      websearch_to_tsquery('english', unaccent(public.catalog_expand_query(p_q))) as tsq,
      unaccent(lower(coalesce(p_q, '')))                           as raw,
      nullif(btrim(coalesce(p_brand, '')), '')                     as qbrand,

      auth.uid()                                                   as uid

      r.catalog_food_id                                                        as catalog_food_id,
      r.id                                                                     as revision_id,
      r.description                                                            as description,
      r.brand                                                                  as brand,

      round(similarity(r.description, q.raw)::numeric, 6)           as f_trigram,

          when q.qbrand is null then 0
          when regexp_replace(lower(unaccent(btrim(coalesce(r.brand, '')))), '\s+', ' ', 'g')

          when r.prep_state = q.qprep                  then 1
          else 0
        end, 6)                                                                as f_prep,
      round(least(1::numeric, ln(1 + coalesce(p.logs_90d, 0)) / ln(21::numeric)), 6) as f_prior,
      round(greatest(0::numeric,

              when 'analytical' then 1.0 when 'survey' then 0.75
              when 'label'      then 0.5 else 0.25 end
          - case when 'energy_mismatch' = any(r.quality_flags) then 0.25 else 0 end), 6) as f_quality,
      round(
        case pref.status when 'eats' then 1 when 'avoid' then 0 else 0.5 end::numeric, 6) as f_eats
    from public.catalog_food_revisions r
    cross join q
    join public.catalog_versions v on v.id = r.catalog_version_id and v.is_active
    join public.catalog_foods    cf on cf.id = r.catalog_food_id
    left join public.food_refs   fr on fr.catalog_food_id = r.catalog_food_id
    left join public.user_food_prefs pref

    left join lateral (

         and li.food_ref_id = fr.id
         and le.user_id = q.uid
         and le.deleted_at is null

    -- their thresholds at 0.25 and 0.45, so this clause is exactly contracts §7's
```

```ts
/**
 * Loads docs/catalog/synonyms.csv into catalog_synonyms (contracts §7), so the table equals the
 * file: every row is upserted on `term`, and every term in the table that the file no longer
 * names is deleted. tests/search/recall.test.ts measures recall against the file, so a table that
 * has drifted from it would make that measurement a lie.
 *
 *   pnpm exec tsx scripts/load-synonyms.ts [--dry-run] [--csv <path>]
 *
 * Env: SUPABASE_URL and the service-role key, read only inside adminClient(). For a Supabase
 * branch, point them at the branch:
 *   SUPABASE_URL=$SUPABASE_TEST_URL SUPABASE_SERVICE_ROLE_KEY=$SUPABASE_TEST_SERVICE_ROLE_KEY \
 *     pnpm exec tsx scripts/load-synonyms.ts
 *
 * A single malformed row refuses the whole run, the same as scripts/apply-food-mapping.ts: a
 * half-loaded vocabulary silently changes what search returns.
 */

import { readFileSync } from "node:fs";
import { adminClient } from "@/lib/server/admin";

const DEFAULT_CSV = "docs/catalog/synonyms.csv";
const HEADER = ["term", "expansion", "source"];

type Row = { term: string; expansion: string; source: string };

function parseCsv(text: string): Row[] {
  const lines = text.trim().split("\n").filter((l) => l.trim().length > 0);
  const head = (lines[0] ?? "").split(",").map((h) => h.trim());
  if (head.join(",") !== HEADER.join(",")) {
    throw new Error(`unexpected CSV header.\n  expected: ${HEADER.join(",")}\n  got:      ${head.join(",")}`);
  }
  return lines.slice(1).map((line, i) => {
    const cells = line.split(",");
    if (cells.length !== HEADER.length) {
      throw new Error(`line ${i + 2}: expected ${HEADER.length} cells, got ${cells.length}`);
    }
    return { term: cells[0], expansion: cells[1], source: cells[2] };
  });
}

function validate(rows: Row[]): void {
  const problems: string[] = [];
  const seen = new Set<string>();
  for (const r of rows) {
    const normalised = r.term.toLowerCase().normalize("NFD").replace(/[̀-ͯ]/g, "");
    if (r.term !== normalised) problems.push(`  "${r.term}": term must be lowercase and unaccented`);
    if (r.term.trim() !== r.term) problems.push(`  "${r.term}": term has surrounding whitespace`);
    if (r.term.length === 0) problems.push("  a row has an empty term");
    if (r.term.split(" ").length > 2) {
      problems.push(`  "${r.term}": catalog_expand_query matches one or two tokens, not ${r.term.split(" ").length}`);
    }
    if (r.expansion.trim().length === 0) problems.push(`  "${r.term}": empty expansion`);
    if (r.expansion === r.term) problems.push(`  "${r.term}": expands into itself`);
    if (seen.has(r.term)) problems.push(`  "${r.term}": named twice`);
    seen.add(r.term);
  }
  if (problems.length > 0) {
    throw new Error(`${problems.length} problem(s) in the synonym sheet:\n${problems.join("\n")}`);
  }
}

async function main(): Promise<void> {
  const argv = process.argv.slice(2);
  const dryRun = argv.includes("--dry-run");
  const csvAt = argv.indexOf("--csv");
  const csvPath = csvAt >= 0 ? argv[csvAt + 1] : DEFAULT_CSV;

  const rows = parseCsv(readFileSync(csvPath, "utf8"));
  validate(rows);

  const admin = adminClient();
  const { data, error: readError } = await admin.from("catalog_synonyms").select("term");
  if (readError) throw new Error(`catalog_synonyms read failed: ${readError.message}`);
  const present = new Set(((data ?? []) as { term: string }[]).map((r) => r.term));
  const wanted = new Set(rows.map((r) => r.term));
  const stale = [...present].filter((t) => !wanted.has(t));

  console.log(`${rows.length} rows in ${csvPath}; ${present.size} in the table; ${stale.length} to delete`);

  if (dryRun) {
    for (const r of rows) console.log(`  would upsert ${r.term} -> ${r.expansion} (${r.source})`);
    for (const t of stale) console.log(`  would delete ${t}`);
    console.log("dry run: nothing written");
    return;
  }

  const { error: upsertError } = await admin
    .from("catalog_synonyms")
    .upsert(rows, { onConflict: "term" });
  if (upsertError) throw new Error(`catalog_synonyms upsert failed: ${upsertError.message}`);

  if (stale.length > 0) {
    const { error: deleteError } = await admin.from("catalog_synonyms").delete().in("term", stale);
    if (deleteError) throw new Error(`catalog_synonyms delete failed: ${deleteError.message}`);
  }
  console.log(`loaded ${rows.length} synonyms, deleted ${stale.length}`);
}

main().catch((e) => {
  console.error(e instanceof Error ? e.message : e);
  process.exit(1);
});
```

## Open questions

1. **FNDDS de-duplication — out of scope, proposed for a later phase.** Every remaining ranking miss has the same
   shape: for a one- or two-word query, FNDDS's prepared-dish variants ("Pie, sweet potato", "Muffin, carrot",
   "Salmon salad", "Scallops, fried") out-score the plain ingredient row, because trigram similarity to a short
   query does not care that "Pie" changes the food. The proposal: when the parsed query is one or two tokens and a
   candidate set contains both a plain ingredient row and prepared-dish rows for the same ingredient, prefer the
   plain row — either as a dish-marker penalty term or as a de-duplication step above the ranker. **This changes
   the score, so it is a contract change and explicitly not this lane's work**; it is recorded here so it is not
   lost. It also interacts with the sizing sign-off (`docs/catalog/sizing.md`): if FNDDS moves to on-demand, most
   of these competitors leave the catalog and the problem shrinks on its own. Needs Devin.
2. **Contracts §7 also names a "typo fold" in `lib/search/query.ts`** — "maps a token to its nearest description
   word when `word_similarity ≥ 0.6`". This lane's brief scopes `lib/search/query.ts` to `expandQuery` only and
   handles typos two other ways: curated `typo` rows in the CSV (`chkn`, `brst`, `potatoe`, `salmom`, `advocado`,
   `bannana`, `cantalope`, `buter`, `maccadamia`) and the `word_similarity(raw, description) > 0.45` recall branch
   in SQL. Both are measured by Task 8. If Devin wants the generic fold as well, it is a contract change, and the
   honest order is: measure first, then decide whether a fold adds anything the two measured mechanisms did not.
3. **`white rice → rice white long-grain` is prep-blind.** `parseQuery` lifts the prep token before the RPC, so
   "white rice" and "white rice cooked" both arrive as `p_q = "white rice"`. The expansion helps the first (the SR
   Legacy long-grain raw row) and denies the second's FNDDS target ("Rice, white, cooked, NS as to fat") its
   "long-grain" term. Task 9's no-regression test decides: if it fails on "white rice cooked", the row is narrowed
   to `white rice → rice white` and the lane re-measures. A prep-aware expansion (passing `p_prep` into
   `catalog_expand_query`) would change the helper's signature and is not in this lane's scope.
4. **`catalog_synonyms` has no RLS, per contracts §7.** It is shared read-only reference data with no user rows, so
   the table grants alone are the boundary — the same argument `catalog_nutrients` rests on. Supabase's advisor
   will still raise `rls_disabled_in_public` for it, because the advisor checks the flag and not the data. Options:
   accept and annotate the advisor finding, or add `enable row level security` + a `for select to authenticated
   using (true)` policy to match every other `catalog_*` table (which would be a contract change, and one the
   20260912090200 grants migration's loop would need widened for). Recommended: match the other `catalog_*` tables,
   after Devin approves the contract change. Until then the migration follows §7 as frozen.
5. **`mct oil` stays unresolved.** Recorded in Task 13's section and repeated here so the decision is visible from
   the plan: it needs a catalog row (OFF or FDC Branded via Lane K, or a label scan via Lane M), not a synonym.
6. **The `duck fat → fat duck` and `avocado mayo → mayonnaise` rows point at foods relevance.md records as absent
   from every imported source.** They cost nothing (a query that matches nothing returns nothing either way) and
