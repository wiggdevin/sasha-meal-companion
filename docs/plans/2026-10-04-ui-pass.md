## Session rule (owner, 2026-10-04)

Every UI change lands in the shared, account-agnostic layer: design tokens, global classes, shared
components and written rules. Nothing is tuned to one account: no email or id checks, no foods,
numbers or copy taken from one profile. Each item is verified on a populated account **and** from an
empty state (no profile, no foods).

## What the owner reported, and what causes it

Kimi's pre-build audit found five root causes behind the list. The work is grouped by root cause,
not by symptom.

| Root cause | Items |
|---|---|
| RC-1 A card-owned flow renders as a second card under the meal card (a sibling `AttachedSheet`), so the header repeats and its numbers come from another selector | U2, U8, U9, U1 |
| RC-2 No enforced component system: button, card and field recipes are copied per screen, and the legacy classes are unlayered, so utilities cannot override them | U4, U10, U11, U12, U13 |
| RC-3 Row state and gesture zones are mixed: focus inside a row reveals Remove, and a checklist input escapes its scroll box | U5, U14 |

| RC-5 Scroll ownership was never specified: inline panels scroll internally with `overscroll-behavior: contain` | U6 |

### Foundation (F) — lands first; every stream builds on it

**U4 Button system.** Asked: one rule-based system; some buttons are too fat, some too plain; states
change; in-button confirmations ("Saved", "Updated", "Logged") instead of toasts.
Cause: four CSS recipes (`.btn-primary` 23 uses, `.btn-ink` 80, `button.well` ~32, `pill-in` used as a
button ~14) plus 10 hand-made 52 px "sheet primaries" with inline height and shadow; `Button` size
`sm` renders 44 px because `.tap` wins; heights 36/40/44/48/52 in use; disabled opacity 40/45/60/70;
success feedback is a violet glow plus a floating toast.
Ships: `components/ui/Button.tsx` v2:
- variants `primary` (olive, the one completing action), `secondary` (paper fill, ink hairline,
  hairline shadow; replaces the plain transparent outline), `tertiary` (beige well), `ghost` (text
  only, for Undo/Edit inside rows), `danger` (red ink; a two-stage confirm), plus `shape="circle"`;
- sizes `sm` 36 px visual with a 44 px hit area, `md` 44, `lg` 52 (sheet and panel primaries only);
  labels never wrap (`nowrap`, ellipsis);
- states: rest, hover (desktop only), pressed (3 % smaller at once, snappy release), focus-visible
  ring, disabled 40 %, `pending` (label width locked, three-dot pulse), `success` (a tick draws in,
  label morphs to the confirm verb, holds 1.6 s, morphs back, success haptic), `error` (3 px shake,
  "Try again", red ink 2.4 s);
- `useActionFeedback` drives it: a control bound to a write confirms in place, so its success toast
  is not shown; failures still raise a `Notice`; an undo with no in-place home keeps its toast.
- the legacy classes move into `@layer components` and take the same metrics, so every unmigrated
  call site already gets the system; the 52 px inline buttons, `pill-in` buttons and hand-made chips
  are migrated to `Button`/`Chip`.
Accept: one Button gallery block shows every variant × size × state at 390 px; no button height
outside 36/44/52; `tests/design/buttons.test.ts` rejects inline button heights, `pill-in` on a
`<button>`, and button-class strings outside `components/ui`; "Ate something else" fits one line.

**U10 Fluid interface rules.** Asked: global written rules for fluid UI, shape morphing, container
transforms, states, interactions, speed, expand/collapse, spring physics, micro-interactions.
Ships: DESIGN.md §Motion gains "Fluid interface rules" (identity, direction, order, speed by size,
interruptibility, gesture follow, morph limits, stagger, feedback timing, reduced motion) and
§Layout gains "Scroll ownership"; KIT.md points to them; the missing CSS twin
`--ease-spring-gentle`/`--dur-spring-gentle` is added; the dock's private spring set
(`dock-motion.ts`) is mapped onto the four named springs.
Accept: the rules are written, linted with Design MD CLI 0.3.0, and every new motion in this pass
cites one of them.

**U11 One card system.** Asked: same rules for every card; some have no shadow and look sunken.
Cause: ~30 card-like containers on the oat ground use a bare `.surface`, `.well`, `.olive-panel` or
`.logged-card-in` without `.shell`, so they carry no `--shadow-card`.
Ships: elevation levels E0 inset (wells, trays, fields — no drop), E1 card (`--shadow-card`), E2
floating (pop-ups, overlay, dock — `--shadow-float`); "never a shadow inside a shadow"; every card
standing on the ground is E1. `Surface` gains `elevation`. The flagged containers are fixed.
Accept: `tests/design/elevation.test.ts` rejects a top-level `.surface` without its shell in the
files fixed here; screenshots of Today board, Foods, Settings, Sasha show no flat card on the ground.

**U12 Three input tiers.** Asked: plain lookup search; component AI input; the master AI bar in the
dock — each with its own look, the first two close.
Cause: wrapped search pills (beige, 6 % ring, no inner shadow) look different from bare fields
(paper, 14 % ring); the magnifier is copied five times.
Ships: tier 1 `SearchField` (paper field, magnifier, clear ×, no send); tier 2 the component ask
box (`PlanComposer`: paper field with an olive-to-wheat rim, a sparkle mark, "+" attach, olive send);
tier 3 the dock bar (charcoal, rim, sparkle). One `SearchIcon`/`SparkleIcon`. All text ≥ 16 px.
Accept: the gallery shows the three side by side; every search uses `SearchField`.

**U6 Scroll ownership.** Asked: an inner scroll that hits its end hands the gesture to the page.
Cause: attached panels have `max-height: calc(100dvh - 330px)` with `overscroll-behavior: contain`;
`SwapSheet` nests a `max-h-[50vh]` contained list inside that.
Ships: inline panels never scroll internally — they grow and the page scrolls (one scroller per
screen); long inline lists cap with "Show all"; horizontal carousels own only the x axis
(`overscroll-behavior-x: contain`, vertical gestures pass to the page); only overlays that lock the
page (modal sheets, the chat overlay) scroll inside with `contain`.
Accept: no `overscroll-contain` left outside overlays; on a 390 × 700 viewport a long Plan panel
scrolls with the page from inside it.

### Today and the meal card (T)

**U1 Ingredient tray sits high.** Cause: the tray's 16 px top margin collapses through the region
(`overflow: clip` is not a block formatting context) and `.details`, landing above the beige tray.
Ships: the region becomes a flow root and spacing moves to padding. Accept: equal 16 px above and
below the ivory tray, measured in the browser.

**U2 + U9 One container for card-owned flows.** Asked: Ask Sasha / Plan, Log what you ate, Search
or new meal, and Swap must be one card with the selected meal on top and only new information below;
no repeated title, time or macros; numbers must agree with the card.
Cause: RC-1; the header chips show this slot's share of what is left of the day (protein-first, so
222 kcal over two open slots reads 111 kcal / 28 g / 0 / 0), next to a card that shows its contents.
Ships: the flow renders inside the meal card's beige tray, in place of the ingredient panel, on the
gentle spring (frame first, content after; closing reverses). The card keeps its hero on top. The
repeated header (`PlanSheetHeader` overline, title, time, target chips) is removed from card-owned
flows; a slim mode row ("Plan with Sasha", "Log what you ate", "Swap") with a close button replaces
it. Any budget figure is labelled as room left ("About 111 kcal left for this meal"), never as the
meal's macros. Panels no longer have their own ivory card, margin or inner scroll.
Accept: in every flow there is one charcoal card; no title/time/macros are repeated; every number in
the panel is either a suggestion's own figure or explicitly labelled as remaining room.

**U9 Meal card layout drift.** Asked: the photo used to fill its side; spacing is off; it shows when
a flow opens. Cause: compact mode sizes the photo to the hero only, so the macro bar row under it is
bare charcoal. Ships: the compact photo fills the card's whole left column (hero plus macro row);
the bar sits in the right column. Accept: no charcoal band under the compact photo, in the list and
with a flow open.

**U3 Attach tab icons.** Ships: camera and attach are bare 22 px glyphs (no pill behind), each
centred in its half of the tab, the tab tall enough to hold them, 44 px hit areas, aria-labels kept.
Accept: centres measured at 25 % and 75 % of the tab width; nothing overflows the tab.

**U5 Ingredient checklist resets.** Cause: the `sr-only` checkbox is absolutely positioned against a
far ancestor outside the panel's scroller, so focusing it scrolls the scroller to the wrong place,
and the result card's `layout="position"` then animates. Ships: the input is contained (`relative`
row), the inner scroller is gone (U6), checks are kept per recipe for the session. Accept: ticking
any row changes only that row's tick and strike-through; nothing moves.

**U7 Swap as a carousel.** Ships: swipe right opens the Swap flow inside the card: a horizontal
snap carousel of image cards (the Foods hub card, extracted as one presentational `SuggestionCard`:
photo from `meal-art`, name, a one-line description from its ingredients, kcal and macros, source
tag). Tapping a card selects it; "Swap to this" confirms in place ("Swapped"). "Edit this meal" and
"Back to the suggested meal" stay as tertiary actions. Accept: carousel scrolls on x only; the page
still scrolls vertically from inside it.

### Foods, Settings and serving search (S)

**U13 Favourite star.** Cause: `.row:focus-within .remove` grows Remove when the star takes focus,
pushing the star 72 px left so Remove lands under the finger. Ships: Remove is revealed only by the
swipe or keyboard focus on the row's face, and it overlays instead of reflowing. Same `FoodRow` on
Eats, Other and Avoid. Accept: ten star taps toggle ten times; Remove never appears.

**U14 Footer row.** Ships: one footer row split in half — "Show all N" left, "Add" right; Add alone
when there is no toggle. Accept: saves one 44 px row per card.

**U15 New recipe.** Asked: no swoop into the button; press opens the cards, close removes them.
Ships: the hub grows open below the section header on the gentle spring and folds back on close;
the button stays in place and shows its pressed state. No shared-element morph. (Kimi argued for
keeping a morph in the other direction; the owner's instruction wins.)

**U16 "Working around a job".** Finding: it always holds one sentence that repeats "Shift the whole
day" above it; its original content was removed in #279. Ships: removed.

**U17 Settings cards.** Ships: "Food preferences" removed (two links to the Foods tab, which the dock
already reaches); "Data & account" becomes one card (export, sync, sign out as rows); "Calendar
reminders" joins the schedule card; the duplicate "Redo setup" link goes (the profile card's Edit
profile opens the same flow). No card grows past the Body profile & units card.

**U8 Serving-aware food search (B).** Ships with the backend's additive fields (`defaultPortion`,
`portions[]` ending in "100 g", `per100g`, `kcalPer100g`): search rows read "1 tbsp (14 g) · 126
kcal", fall back to "100 g · N kcal", then to today's line; adding uses the default portion; the
ingredient stepper steps by the portion when a component carries one, else by its unit.
Accept: works with and without the backend fields deployed.

**U23 Plate photo confirms before it logs (B3, from the backend's AI-integration audit).** Cause: the
Plan panel's "Log it" shows photo-ideas macros, then commits a separate capture draft the user never
saw. Ships: the capture draft shows in the existing confirm editor inside the card and commits only on
confirm; the same for a menu pick or "I had…". Accept: a test proves nothing commits before confirm.

**U24 Swipe tray labels fit (owner, gallery).** "Release to delete" is clipped in the 114 px armed pill.
Ships: each stage picks the label that fits its measured width ("Release to delete" → "Release" → the
glyph); nothing clips; the accessible name stays "Delete <meal>".

**U25 Photo and menu picks as image cards (owner, gallery).** The menu result's picks are tall
`button.well` blocks forced into ovals by the global pill radius. Ships: the shared `SuggestionCard` in
the same horizontal carousel as Swap and the recipe hub (photo, name, kcal and macros, the tip as its
line); a tap expands it in place into the larger card; logging goes through U23's confirm.

**U26 A carousel card expands in place (owner note).** "Every time one of these middle cards is selected,
it should grow smoothly and take up the space provided so the other smaller meal cards are pushed out of
the way, with a visible X … then it should shrink back into the horizontal scroll." Ships in the shared
card family (recipe hub, swap, photo picks): a container transform to the row's full width, neighbours
slide aside, a 44 px close, the exact reverse on close with the row's scroll restored.

### Dock, weigh-in and Sasha (D)

**U18 Camera only.** Ships: the Scan tile is removed; Camera takes the photo; a barcode in the still
is read first (the existing zxing worker on one frame), otherwise the photo goes to the AI as a plate,
menu or label, with the existing "read it another way" switch. Accept: the tray shows no Scan; a
photo of a barcode logs that product.

**U19 Weigh-in.** Cause: the field sits inside `.matte`, whose text roles turn cream, on a light
well; Send posts "I weigh 215 lb this morning" to the chat. Ships: ink-on-paper field (contrast
≥ 4.5:1), Send logs directly through the existing weight path, confirms in the button ("Logged", a
success haptic where supported), then the field morphs into follow-ups: Undo (8 s, the real undo),
"See your trend" (opens the chat overlay with the weight chart), "Suggestions". No chat turn for the
log itself. Accept: log + undo round trip in the browser, unit kept as entered.

**U20 Conversations.** Cause: `button.well` forces every row into a tall pill; there is no delete,
and with the 8-chat cap an account at 8 chats cannot start a new one. Ships: a real list — search
field (fuzzy over titles at once, server search over messages from 3 characters, B), rows with
title, relative time and a swipe-left Delete with an in-button two-step confirm, a row menu (Rename,
Clear messages, Delete) as the tap equivalent, grouped Today / This week / Earlier, "New chat".

**U21 Sasha header and thinking.** Ships: the header carries a living AI mark (the three orbs at
rest, breathing slowly; faster while Sasha works), a scope chip ("On Today"), and a visible
Conversations control; the thinking state shows in the header and in the transcript.

**U22 AI scope and the chat overlay (B).** Ships: component inputs act on their component only and
answer in place; the dock's ask bar is page-aware and opens a chat overlay over a dimmed page
instead of routing to /coach; the page underneath keeps its scroll and state; back, Escape, the
scrim and the close button dismiss it. Each message carries `scope: { kind: "page", page }`.

**U27–U30 Occasion-aware meals (B, PR #362, after it lands).** U27 the swap carousel passes
`clock: slot.time, date` to `swapAlternatives`; U28 an empty generated slot shows its
`generatedShortagesForDay` reason as a quiet line; U29 an under-target card shows its
`generatedMissesForDay` line; U30 Today's protein notice shows only when a slot has no protein at all:
"{n} eligible proteins for {m} meals. Add a verified protein in Foods."
