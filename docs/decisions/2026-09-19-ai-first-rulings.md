## Jev evaluation

Helps (built here): intent + argument routing (D4a, ~300 ms, confidence-gated), claim-without-action
verification (D4b), ranking code-built candidates (D4c), free-text → typed preferences (D4d).
Considered and deferred: catalog-hit reranking for "add X to avoid" when several rows match (the
same-name widening already covers the reported bug); gluten/dairy Noul over label ingredient text
for unverified items (a T3-label-scan follow-up, cut by Devin on 2026-09-18). Not suitable: any
generative turn (recipes, explanations, the reply text), arithmetic (portions, macros), anything
needing catalog lookups — code and Gemini keep those.

## Executor deviations and clarifications

- **Mifflin reference:** for a male aged 25, 180 cm and 80 kg, the implemented formula returns
  1,805 kcal. The 1,780 kcal reference belongs to age 30; tests preserve both values.
- **Fallback weight:** `resolveTargets` does not load the latest weigh-in itself. Its derivation
  fallback uses `Settings.weightKg`; onboarding and `update_profile` write a weigh-in-aware
  `activeTargetProfile`, which remains the approved-profile path.
- **Remove from Eats:** `remove_from_eats` is an alias for setting the food to `avoid` with the note
  “removed from Eats by the coach on <date>”. Nothing is deleted, so the food and note can be
  restored.
- **No-nuts preference:** the current reference model has only the `peanut` allergen key, so the
  confirmed `no_nuts` chip maps to peanut today. Tree-nut keys require a future reference-model
  expansion.
