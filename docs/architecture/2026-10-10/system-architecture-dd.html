Meal Companion system architecture

Phone PWA, Next.js on Vercel sfo1, Supabase us-west-1 and the outside providers. This version adds every route group, the ten cron jobs and the MCP route. Facts checked against code at 7405f41f.

How a phone request moves

  • The phone writes the store and IndexedDB first. The sync engine sends queued ops 1.5 s later (lib/sync/account-sync.ts:31) to /api/sync/ops, which calls apply_sync_op (app/api/sync/ops/route.ts:52).
  • Every route checks its own auth. The middleware matcher skips /api/ (middleware.ts:15); requireUser verifies the JWT and the x-smc-account header (lib/server/auth.ts:27-46).
  • The phone also calls Supabase directly: sign-in (app/sign-in/page.tsx:98) and PostgREST writes to user_foods, food_refs, user_food_prefs and the apply_sync_op RPC (components/add-food/catalog-food.ts:34-64).

Which client runs

  • User routes use the request-scoped client, so RLS applies.
  • The admin (service-role) client runs the cron routes, the token routes and the MCP tools. Coach and plan routes pass adminClient() into their libs (app/api/coach/route.ts:71, app/api/plan/ideas/route.ts:32).
  • Cross-tenant safety on that path rests on each query adding .eq("user_id"). Canary tests cover it (tests/tenancy/admin-canary.test.ts).

MCP runs tools on the admin client

The MCP token is an opaque smc_ string, not a Supabase JWT, so RLS cannot apply. withTokenUser resolves one user id from the token row and hands the tool the admin client (lib/server/privileged.ts:1-8, 49). Each tool then filters by that id in its own query.

Leads for the audit

Found while checking these three areas. Each one is a fact in code; none is yet a confirmed defect.

#LeadFact
1MCP set_constraints skips the hold recomputeThe HTTP route re-derives the target after a conditions change (app/api/constraints/route.ts:31-35 calls recomputeAfterHoldChange). The MCP tool calls putProfile and stops (lib/mcp/coach-tools.ts:55). A condition set over MCP (for example pregnancy) leaves the stored target on its old pace until a later settings op or an HTTP save.
2Nightly JSON backup lists a fixed set of tablesTABLES holds 32 names and its comment names one source migration (app/api/jobs/backup/route.ts:33-52). At least 37 user-keyed tables from later migrations are absent, among them shopping_*, recipe_plan_*, care_*, coach_action_undos, coach_action_receipts, user_dietary_profiles, food_signal_events, taste_chip_receipts, onboarding_events. The job also gets one fire a day with maxDuration 300 (route.ts:29) and a 2 h stale lease (route.ts:58).
3Coach transcribe has no flag check and no per-user limitEight other coach routes answer 404 when coachEnabled() is off. app/api/coach/transcribe/route.ts:25-31 does not, and limits only by IP before it transcribes with the admin client in hand.
4Coach turn budget fails open and can raceassertTurnBudget counts successful ai_calls rows and returns on a read error (lib/server/coach.ts:104-112). Parallel turns all read the same count. The coach route has an IP limit only (app/api/coach/route.ts:68).
5Coach Undo routes limit after authapp/api/coach/undo/route.ts:40-41, 62-63 and undo/[id]/route.ts:29-30 have no pre-identity IP limit, unlike the other coach routes.
6Cron schedule and its stated plan disagreemedia-sweep/route.ts:3 says the job is daily because Vercel Hobby allows nothing faster. vercel.json:4-13 holds a 15-minute job, an hourly job and four multi-fire jobs.
7Three jobs copy the secret checkbackup/route.ts:124-132, media-sweep/route.ts:39-47 and oura-pull/route.ts:46-54 define their own bearerOk. The other seven use cronSecretOk (lib/server/jobs.ts:22-30).
8Flag-off answers differ between jobsestimate and weekly-proposal answer 503 when ESTIMATOR_ENABLED is unset (estimate/route.ts:46-48, weekly-proposal/route.ts:113-115), so each cron fire logs a failure. oura-pull and weekly-review answer 200 (oura-pull/route.ts:63, weekly-review/route.ts:80).
9First constraints write has no compare-and-swapAt revision 0, putProfile upserts (lib/server/constraints.ts:162-166). Two first writers both succeed and the second overwrites the first. The HTTP route and the MCP tool share this path.
