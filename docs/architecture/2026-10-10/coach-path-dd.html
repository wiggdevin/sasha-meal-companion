Coach request path

One coach turn, from the ask box to server Undo. Each step shows which database client it uses: RLS (the user's session) or ADMIN (service role). Audit 2026-10-10, repo at 7405f41f. File and line references are in coach-path.md.

1. The turn

The server returns grounded actions and never writes them. The phone applies them, then records an Undo token. Detail level: faithful, 12 nodes.

2. callModel, the one governed model path

Jev, Gemini and OpenRouter calls all pass these gates in this order. Gates 1 to 6 refuse with no ledger row and no provider I/O.

3. Apply and Undo

Returns for messages 5, 7 and 9 are left out. The database functions are SECURITY DEFINER and read auth.uid() from the caller's JWT.

Session (RLS)

  • Thread, seq, replay and history reads and writes
  • Catalog search, targets, constraints, rule review
  • Every undo route and the sync op-log

Admin (service role)

  • Turn budget, circuit, spend reservation and the ai_calls ledger
  • Day context, totals, ref minting, grounding policies
  • Plan-thread insert and the transcribe route

Where it bends

Scope narrows actions but does not authorize. The budget counts only Gemini rows. See the findings list in coach-path.md.
