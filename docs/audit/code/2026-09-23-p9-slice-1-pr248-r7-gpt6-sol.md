1. [BLOCK] **A failed save can still be lost at the end of a switch.** `lib/device/unsaved-store.ts:39-41,51` returns when no edit is pending or the generation is stable. `lib/device/session-binding.ts:52-60` then resumes from an `await` before unbinding. An A callback can save in that gap; if localStorage refuses the write, `lib/store.ts:193-216` keeps it only in memory, which the switch then purges. Close the handoff gap by preventing new A writes until unbind, or perform a final check and unbind without an async boundary. Test a failed save queued between flush resolution and unbind.

2. [BLOCK] **A saved edit becomes inaccessible when another tab changes its base blob.** On a base mismatch, `lib/device/unsaved-store.ts:63-68` moves the only recovery copy to a `held:*` key and returns; `lib/device/session-binding.ts:25-26` marks the account ready. No consumer reads that held key, so A’s local-only edit disappears from the app if another A tab saved a different blob meanwhile. Reconcile the copies or keep recovery blocked with an actionable path. Test two same-account tabs making distinct edits across the switch.

[FIX] **A lost target response can replay an older target.** `lib/targets/client.ts:203-211` restores the previous queued revision after a direct send fails, even if the server accepted the newer revision before its response was lost. This race predates the PR. Reconcile the newer request ID against server authority before restoring or replaying the older intent.
