[BLOCK] An in-flight weight Undo can delete the next account’s weigh-in. `lib/coach/apply-body.ts:90-115` captures A’s handle and awaits `drainWeighIns`, then calls `deleteMorningWeight` without that handle. The delete captures whichever account is bound at that moment (`lib/today/water-and-weight.ts:305-313`); the A-handle check at `apply-body.ts:117` comes after the DELETE. Pass `account: h`, check `assertCurrent(h)` after the drain, and test an A→B switch before the delete with a B weigh-in on that date.

2. [FIX] Keep the newer target request pending when its response is lost. A direct send restores an older queued revision on transport failure (`lib/targets/client.ts:183-209`), even if the server accepted the newer one. This race already exists without a switch on `origin/main:lib/targets/client.ts:176-199`; the PR does not worsen it. Reconcile the newer request by its ID before replaying the older revision.

3. [FIX] Order same-day weigh-ins at the server. The PR can send an older queued weight concurrently with a newer save (`lib/health/weigh-in-client.ts:267-304,358-392`), while the RPC overwrites by arrival order (`supabase/migrations/20261019090000_manual_weigh_in.sql:96-104`). The same concurrent paths exist on `origin/main:lib/health/weigh-in-client.ts:234-268,314-347`. Add a durable per-day ordering rule so a late older request cannot erase a correction.

4. [FIX] Account switches remove offline resources that are still needed. `lib/device/forget.ts:24,73-80` deletes the account’s saved food refs and the service worker shell cache. The ref is what lets a previously resolved catalog food log offline (`lib/log-client.ts:113-137`); without it, the catalog confirmation cannot proceed (`components/LogFoodSheet.tsx:282-283`). The worker’s offline navigation also depends on that shell cache (`public/sw.js:70-79,93-95`). Preserve account-scoped refs and a safe offline shell, or rebuild them before treating the returning account as offline-ready.
