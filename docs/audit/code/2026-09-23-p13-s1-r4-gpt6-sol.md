- **#8 (chart scoring) — NOT CLOSED [BLOCK].** [score.ts:62-80](/Users/zero-suminc./projects/clients/Sasha/mc-p13-s1/scripts/eval/lane-bench/score.ts#L62-L80) now checks unit, series-label and caption-number content, but two gaps make it gameable:
  - **Caption numbers are checked against a pooled set, not attributed per point.** `allowed` is a flat `Set` of every expected y-value (`expect.points.map(([, y]) => y)`), so a caption that *swaps* which value belongs to which day still passes, because both numbers are still "in the set."
  - **Series-label check is a loose substring.** `expect.label.some((word) => seriesLabel.includes(word))` passes `"Calories burned"` against the expected words `["kcal", "calorie"]`, because `"calories burned"` contains `"calorie"` — wrong verb, same substring.
  - **Reproduced independently** (`pnpm exec tsx`, run from repo root):
    ```
    expected = { chart: "kcal_week", points: [["Mon",1800],["Tue",2000]], unit: "kcal", label: ["kcal","calorie"] }
    block = { chart: "kcal_week", unit: "kcal",
      series: [{ label: "Calories burned", points: [{x:"Mon",y:1800},{x:"Tue",y:2000}] }],
      caption: "Mon was 2000 kcal and Tue was 1800 kcal." }   // values swapped
    isCorrect(expected, block)  →  true
    ```
    A chart with the right numbers on the wrong days, and a series labelled for the wrong thing, scores "correct." The lane report's ui_chart accuracy figures (63%/88% in the current `docs/evals/2026-09-23-lane-bench.md`) are more trustworthy than before the fix, but are still not a reliable accuracy measurement — round 3's blocker survives in narrowed form.

## New findings (not raised in rounds 1–3)

- **[WARN] Gemini thinking tokens are silently excluded from cost, while `usageKnown` says cost IS known.** [adapter.ts:155-161](/Users/zero-suminc./projects/clients/Sasha/mc-p13-s1/lib/ai/adapter.ts#L155-L161): `outputTokens` reads only `candidatesTokenCount`; it never reads `usageMetadata.thoughtsTokenCount` (a real, separate field — confirmed in `node_modules/@google/genai/dist/genai.d.ts:6249`, documented as billed and additive to the total). Every candidate model in this bench runs with `thinkingLevel` `LOW` or `MINIMAL` (never off), so any call that does billed thinking work reports a cost lower than what was actually charged, while `usageKnown` is `true` — the opposite failure mode from #5 (known-but-wrong, not correctly-flagged-unknown). This directly undercuts the fix commit's own claim that unknown usage is "never zero": here it can be non-zero-but-understated and still called known.

- **[WARN] Text-capture accuracy scoring accepts a wrong food and any portion.** [score.ts:97-100](/Users/zero-suminc./projects/clients/Sasha/mc-p13-s1/scripts/eval/lane-bench/score.ts#L97-L100): the `labels` branch matches by substring and checks only item *count*, never quantity or grams. Reproduced:
    ```

    →  true
    ```
    `"eggplant"` contains `"egg"`. The `capture_text` lane's 83%/83% accuracy figures in the current report can include a wrong food or a wrong amount scored as correct.
