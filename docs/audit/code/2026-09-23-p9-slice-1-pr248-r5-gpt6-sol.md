1. [BLOCK] **An account switch can discard an edit that exists only in memory.** When `localStorage.setItem` fails, `saveStore` retains the edit in `cached` and returns normally (`lib/store.ts:202-216`). Sync waits 1.5 seconds after the save (`lib/sync/account-sync.ts:63-73`), but a switch stops that timer and clears the cache (`lib/sync/account-sync.ts:75-82`; `lib/device/session-binding.ts:42-44`; `lib/store.ts:382-386`). An immediate A→B→A switch can therefore erase A’s edit. Preserve the failed write for A until it is durable, or report the failure and prevent a silent transition. Test a storage failure followed by an immediate switch and return.

2. [BLOCK] **Deleting the legacy database can erase work queued by an old tab.** Adoption decides `smc` is deletable from a one-time outbox count (`lib/device/legacy-adoption.ts:182-189`), then issues `deleteDatabase`; `onblocked` is treated as completion even though the delete remains pending (`lib/device/legacy-adoption.ts:169-175,201-205`). An old tab may remain open when worker navigation fails (`public/sw.js:55-56`). It can append an op after the count; when that tab closes, the pending delete removes the op. Keep `smc` while old writers may exist, or coordinate deletion and recheck under an exclusive condition. Test a late write from an open old tab.

3. [FIX] **A lost target response can replay an older target.** A direct send restores the previous queued revision after a transport error (`lib/targets/client.ts:183-209`), even if the server accepted the newer request. This is a pre-existing follow-up. Reconcile the newer request ID with server authority before restoring or replaying the older revision.

4. [FIX] **Same-day weigh-ins still use arrival order.** An older queued request can race a newer save (`lib/health/weigh-in-client.ts:267-304,358-392`), and the server upsert has no ordering guard (`supabase/migrations/20261019090000_manual_weigh_in.sql:96-104`). This is a pre-existing follow-up. Enforce per-day ordering at the server and test reversed arrival.
