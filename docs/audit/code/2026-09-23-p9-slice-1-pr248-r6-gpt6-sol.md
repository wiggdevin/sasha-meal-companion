Verdict: DO NOT SHIP — 3 BLOCK, 4 FIX, 0 NIT

1. [BLOCK] **A save can be lost while the pre-switch flush waits.** `flushUnsavedStore` snapshots A’s in-memory store, then awaits the IndexedDB write (`lib/device/unsaved-store.ts:31-42`). A remains bound until that await finishes (`lib/device/session-binding.ts:47-61`), so an in-flight callback can make another `saveStore` that also fails localStorage (`lib/store.ts:193-216`). The switch then clears that newer, uncopied edit. Block new writes during the flush or recheck and flush until the store generation is stable. Test a second failed save while `putMeta` is pending.

2. [BLOCK] **Recovery can discard the only copy of an edit.** A failed `getMeta` is swallowed (`lib/device/unsaved-store.ts:45-52`), and the account is marked ready anyway (`lib/device/session-binding.ts:20-27`). The user can then edit the older localStorage store. On the next return, a different raw blob causes the saved copy to be deleted without checking whether it contains the earlier edit (`lib/device/unsaved-store.ts:53-59`). Keep the gate closed on an unreadable recovery copy; reconcile a changed base before deleting it. Test a transient read failure, a new save, and a return.

3. [BLOCK] **Legacy adoption can overwrite another tab’s unsent work.** `adoptOwnedRecords` reads a pending list and writes its merged snapshot in separate transactions (`lib/device/legacy-adoption.ts:97-110`), outside the lock used by weigh-in writers (`lib/health/weigh-in-client.ts:124-150`). If another A tab queues a weight between those calls, adoption removes its pending request; the local weight then has no retry path. Merge atomically in the same cross-tab lock or one IndexedDB transaction. Test that interleaving.

4. [FIX] **An accepted target correction can be followed by an older queued target.** A direct send restores the previous queued revision after a transport error even when the server accepted the newer request (`lib/targets/client.ts:183-209`). Reconcile the newer request ID with server authority before restoring or replaying the older one.

5. [FIX] **Same-day weigh-ins still resolve by arrival order.** A queued drain and a newer save can post concurrently (`lib/health/weigh-in-client.ts:267-303,358-392`); the RPC overwrites the day with whichever arrives last (`supabase/migrations/20261019090000_manual_weigh_in.sql:96-104`). Enforce per-day ordering at the server and test reversed arrival.

6. [FIX] **A transient legacy database check can permanently skip owned-row adoption.** `openLegacy` returns `null` when `indexedDB.databases()` fails (`lib/device/legacy-adoption.ts:49-59`), yet adoption still writes the “adopted” marker (`lib/device/legacy-adoption.ts:197-205`). Later attempts skip `copyOwnedRows`. Record successful inspection separately from “no database,” or make owned-row copying safely repeatable. Test failure followed by a successful retry.

7. [FIX] **The Phase 9 spec now directs future work toward behavior this review removed.** It says account headers become required later and calls for deleting `smc`, account caches, and the offline shell (`docs/specs/phase-9-tenancy-blank-slate.md:268-270,286-299`). This branch requires the header now and retains those stores (`lib/server/auth.ts:32-43`; `lib/device/legacy-adoption.ts:171-185`; `lib/device/forget.ts:1-6`). Update the spec to the reviewed safety behavior before it guides another slice.
