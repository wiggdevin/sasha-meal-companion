Verdict: DO NOT SHIP — 2 BLOCK, 2 FIX, 0 NIT

1. [BLOCK] **Onboarding can pass a stale floor to the checked writer.** Phase 12 passes the floor computed from the approved build, but reads the latest body-mass sample only after the weigh-in step (`docs/specs/phase-12-coach-tools.md:125-143,190-197`). Phase 10 validates the build against its own inputs, not against a sample received since approval (`docs/specs/phase-10-conversational-onboarding.md:769-782,804-807`). If Health supplies a higher weight before completion, the writer can verify the new sample snapshot while checking the target against the old, lower floor. Recompute or reject the floor when the latest sample differs from the build’s weight input. Test ingestion between approval and completion.

2. [BLOCK] **The round 16 Undo check can validate the wrong revision.** The spec checks the server’s active predecessor (`docs/specs/phase-12-coach-tools.md:148-159`), but the phone’s Undo token retains its cached prior revision ID (`lib/coach/apply-profile.ts:66-86,180-189`). If another device wrote a newer, above-floor revision, the server can return `undoAvailable: true` for that revision while the stale phone later tries to restore its older, below-floor revision. Bind the check and Undo token to the *same* revision ID, or refuse a stale predecessor. Carry `undoAvailable` through the client and card; test two devices with different cached revisions.

3. [FIX] **The contract query cannot detect an active headerless old client.** `client_builds` is populated from `x-smc-client`, and the query checks only recorded builds (`docs/specs/phase-12-coach-tools.md:193-213`). Phase 9 expressly allows old `manual` account tabs without that header to keep working (`docs/specs/phase-9-tenancy-blank-slate.md:443-449`). Such a tab can make requests today while the query returns zero rows. Record missing or invalid headers as an old-build sentinel and include recent sentinel activity in the M-b gate; test that case.

4. [FIX] **A stale-profile refusal can remain in the weigh-in target queue indefinitely.** The spec calls for one re-read and retry on `409 stale_profile` (`docs/specs/phase-12-coach-tools.md:141-145`), but `saveMorningWeight` enables `queueOnFailure` (`lib/today/water-and-weight.ts:257-267`), and the current client queues every failed post while its drain simply retries failures (`lib/targets/client.ts:190-198,202-218`). Specify a typed `stale_profile` path that rebuilds and retries once, then removes or parks the request with a visible notice. Test a concurrent profile change during a queued weigh-in retarget.
