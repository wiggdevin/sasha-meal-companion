# Audit: phase-11 round 3 (GPT-6 Sol, codex exec, xhigh, read-only)

---

Verdict: DO NOT SHIP — 9 BLOCK, 2 FIX, 0 NIT

1. [BLOCK] **“Forget” still promises more than deletion does.** The Settings copy and success criterion say a deleted fact stops coming up unprompted everywhere (`docs/specs/phase-11-conversations-memory.md:423-435,601-604`). The spec leaves the original thread’s summary intact, and that summary is injected on later turns (`lib/coach/history.ts:106-123`); the prompt instructs the model to carry its facts forward (`lib/coach/prompt.ts:110-118`). Narrow the copy, criterion, and Preview test to admit unsolicited use in that thread, or suppress the fact there. This finding concerns the shipped promise, not deferred automatic inference.

2. [BLOCK] **The stale-goal resolution cannot use the data shape it specifies.** Account memories become `string[]` at `docs/specs/phase-11-conversations-memory.md:341-345`, but the proposed guard tests `m.kind` and references `memories` while constructing the same `Promise.all` result (`:357-364`; current fetch at `lib/server/coach-context.ts:182-198`). Keep typed rows, fetch them before deciding whether to load the profile, and test an ordinary turn with a goal memory after the structured goal changes.

3. [BLOCK] **Medical screening has no defined failure behavior.** Both write routes rely on one Jev question (`docs/specs/phase-11-conversations-memory.md:265-275,309-317`), while `systemOne()` returns `null` for a missing key, budget rejection, timeout, or malformed answer (`lib/ai/typesafe.ts:239-261,284-326`). The spec gives no threshold or refusal rule for that result, yet guarantees no medical memory (`docs/specs/phase-11-conversations-memory.md:599-600`). Define a fail-closed result and threshold for create and edit, with unavailable-provider tests.

4. [BLOCK] **Explicit-only writing is enforced only by a model prompt.** The prompt says to emit `remember_fact` only after a direct request (`docs/specs/phase-11-conversations-memory.md:303-308`), but the specified POST checks medical content, not whether the user asked (`:309-317`). The client automatically applies returned actions (`components/coach/CoachShell.tsx:150-165`). Bind a chat-created memory to the authenticated source turn and verify the request, or require a separate user confirmation before writing. Test an unasked action emitted by the model.

5. [BLOCK] **Explicit writes still race.** The scope cut assumes one writer (`docs/specs/phase-11-conversations-memory.md:150-157`), but dedupe, replacement, cap eviction, and “Forget everything” are separate described operations (`:318-336,417-422`). Two devices can both see no match and insert; an in-flight POST can insert after forget. The client’s guard is process-local and a timed-out write continues (`lib/coach/apply-client.ts:33-46,122-153`). Specify an account-serialized database transaction and idempotency key; test concurrent creates and create-versus-forget.

6. [BLOCK] **The exhaustive dedupe path exceeds its own action budget.** It permits up to 200 Jev calls for one save (`docs/specs/phase-11-conversations-memory.md:318-326`). Each call has a default three-second deadline (`lib/ai/typesafe.ts:12,284-287`), while the client reports a timeout after 20 seconds (`lib/coach/apply-client.ts:35,41-46`). Use a bounded candidate strategy or batch judgment with an explicit failure result, and test near the 200-row cap.

7. [BLOCK] **Deleted-thread protection is not atomic across concurrent transactions or direct writes.** A trigger that merely reads `deleted_at` (`docs/specs/phase-11-conversations-memory.md:215-226`) can check an active parent before a concurrent soft delete commits, then insert afterward. Also, the proposed `soft_delete_thread()` clears citations only when its route is used (`:227-232`), while authenticated users currently have direct UPDATE access to their threads (`supabase/migrations/20260911000500_rls.sql:12-22`). Serialize insert and delete with a conflicting parent-row lock, and enforce citation clearing for every allowed deletion path. Test that interleaving and a direct PostgREST update.

8. [BLOCK] **The new action lacks a complete provider-to-client contract.** The spec names the `CoachAction` union, grounding passthrough, and client dispatcher (`docs/specs/phase-11-conversations-memory.md:297-310,570-573`). The model actually emits a compact flat wire action whose fields are expanded and strictly parsed (`lib/coach/actions.ts:188-270,311-405`); persisted actions are parsed again (`:518-560`), and Undo requires a token (`lib/coach/apply-shared.ts:25-56`). Specify `remember_fact` in those schemas and positional arguments, its history rendering, and its Undo token. Test provider wire through persisted replay and apply.

9. [BLOCK] **The unavailable-Jev recall check cannot pass its stated test.** The fallback flags a retrospective claim only when no recall tool ran and account memory is empty (`docs/specs/phase-11-conversations-memory.md:408-411`). It therefore passes a fabricated claim after an empty or unrelated recall result, contrary to the required unavailable-Jev test (`:527-529`). The proposed 500-character slice can also omit later returned hits (`:395-403`). Define bounded per-hit evidence and a fail-safe response when no evidence supports the claim; test empty, unrelated, and truncated results.

10. [FIX] **Add memories to the scheduled backup.** The spec discusses the `pg_dump` script (`docs/specs/phase-11-conversations-memory.md:110-114,183-187`), but the daily Vercel backup uses a fixed table list (`vercel.json:2-9`; `app/api/jobs/backup/route.ts:36-48,119-125`). `coach_memories` will be absent from that backup. Add it to the table inventory and restore test.

11. [FIX] **Repair existing message ownership during migration.** The proposed trigger corrects `coach_messages.user_id` on future inserts or updates (`docs/specs/phase-11-conversations-memory.md:284-295`), but current RLS has allowed that column to disagree with the thread owner (`supabase/migrations/20260911000500_rls.sql:55-68`). Backfill existing rows from `coach_threads.user_id`, check for mismatches, and test a pre-migration forged row.
