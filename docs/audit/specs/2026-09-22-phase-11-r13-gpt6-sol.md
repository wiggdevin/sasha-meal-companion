1. [FIX] **Authenticated users can forge the list’s derived fields.** The spec calls the message trigger the sole writer of `last_message_preview` and `last_message_at` ([spec:340](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-11-conversations-memory.md:340), [spec:356](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-11-conversations-memory.md:356)), but its thread guard restricts only changes to `deleted_at` ([spec:495](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-11-conversations-memory.md:495)). The existing grant permits authenticated `INSERT` and `UPDATE` on the whole `coach_threads` table ([RLS migration:17](/Users/zero-suminc./projects/clients/Sasha/meal-companion/supabase/migrations/20260911000500_rls.sql:17)). A direct PostgREST call can therefore set a fake preview or future timestamp. Protect both fields on insert and update while allowing the maintenance function to write them; test direct authenticated calls.

2. [FIX] **The backfill preserves timestamps the spec identifies as wrong.** `persist()` and `writeWeeklyReview()` currently write an application timestamp after inserting the message ([coach-threads.ts:173](/Users/zero-suminc./projects/clients/Sasha/meal-companion/lib/server/coach-threads.ts:173), [coach.ts:132](/Users/zero-suminc./projects/clients/Sasha/meal-companion/lib/server/coach.ts:132)). Round 12 removes those future writes, but the proposed backfill updates `last_message_at` only where it is null ([spec:393](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-11-conversations-memory.md:393)). Existing non-null values remain different from the latest message’s `created_at`. Recompute the timestamp for every thread with messages during migration, and test a pre-migration thread with a non-null value.

3. [FIX] **The cross-device, in-flight guarantee exceeds what the lock enforces.** The spec promises that a turn in flight when deletion happens cannot continue a deleted conversation ([spec:1023](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-11-conversations-memory.md:1023), [spec:1034](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-11-conversations-memory.md:1034)). If a turn’s message inserts win the row-lock race, deletion can commit before its response reaches another device. That device still dispatches the reply and automatically applies its actions ([coach-turn.ts:799](/Users/zero-suminc./projects/clients/Sasha/meal-companion/lib/server/coach-turn.ts:799), [CoachShell.tsx:238](/Users/zero-suminc./projects/clients/Sasha/meal-companion/components/coach/CoachShell.tsx:238), [CoachShell.tsx:150](/Users/zero-suminc./projects/clients/Sasha/meal-companion/components/coach/CoachShell.tsx:150)). State the narrower commit-order guarantee and test this two-device race, or add a gate that prevents those late actions.
