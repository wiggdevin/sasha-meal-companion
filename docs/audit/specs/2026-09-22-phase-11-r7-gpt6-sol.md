Verdict: DO NOT SHIP — 2 BLOCK, 3 FIX, 0 NIT

1. [BLOCK] **Recall can mistake the current thread for an earlier conversation.** The proposed port receives only `(userId, query, limit)`, and the search includes the user’s threads without excluding the active one (`docs/specs/phase-11-conversations-memory.md:389-396`). Yet the verifier treats returned snippets as evidence about an *earlier, different* conversation (`:422-427`); its proposed evidence records only snippet text (`:404-412`). Pass the active thread ID from `runTurn()` (`lib/server/coach-turn.ts:237`) into the search, exclude it server-side, and retain source thread and date in verifier evidence. Test a matching message in the current thread alongside a different older thread.

2. [BLOCK] **The unavailable-Jev path cannot enforce the recall claim guarantee.** It flags retrospective phrases rather than checking a claim against results (`docs/specs/phase-11-conversations-memory.md:432-443`). After an empty recall, an answer such as “Peanuts” to “What did I say I was avoiding?” makes an unsupported claim with no retrospective phrase. The reused correction path also ends in an action-specific “I have not logged that yet” response (`lib/server/coach-turn.ts:651-665,758-761`). Define a separate recall failure path that gives a neutral “cannot verify” answer when evidence or verification is unavailable, and test empty, unrelated, and unavailable results.

3. [FIX] **New weekly reviews will have no preview.** The spec fills `last_message_preview` in `persist()` and backfills existing rows once (`docs/specs/phase-11-conversations-memory.md:260-272`). Weekly reviews use a separate writer that inserts a message and updates only `last_message_at` (`lib/server/coach.ts:123-133`). Maintain the preview for that writer too, preferably at the message-write boundary; test a weekly review created after migration.

4. [FIX] **The weekly-review row remains directly mutable despite its pinned treatment.** The spec hides Rename and Delete in the UI (`docs/specs/phase-11-conversations-memory.md:221-225`), but the existing DELETE route filters by owner and ID, not kind (`app/api/coach/threads/[id]/route.ts:62-66`), and owner RLS permits UPDATE and DELETE (`supabase/migrations/20260911000500_rls.sql:12-22`). Phase 10’s planned restriction covers onboarding, not weekly review (`docs/specs/phase-10-conversational-onboarding.md:607-616`). A direct deletion hides the review; the job then creates another active weekly-review thread (`lib/server/coach.ts:105-116`), while the proposed purge excludes the deleted one (`docs/specs/phase-11-conversations-memory.md:525-528`). Restrict weekly-review mutation in RLS and the endpoints, and test direct API and PostgREST writes.

5. [FIX] **Historical nutrition numbers need an explicit current-state rule.** Recall returns old message content (`docs/specs/phase-11-conversations-memory.md:394-398`), which can include superseded calorie or macro targets. The current day context reads revision-backed targets (`lib/server/day-context.ts:179-204`), but context failure is tolerated (`lib/server/coach-turn.ts:491-503`). Mark recalled numbers as historical; require a successful current target read before using them for present-day advice. Test a recalled target that conflicts with the latest revision.
