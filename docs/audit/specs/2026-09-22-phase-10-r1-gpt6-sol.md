# Audit: phase-10 round 1 (GPT-6 Sol, codex exec, xhigh, read-only)

---

Verdict: DO NOT SHIP — 10 BLOCK, 7 FIX, 0 NIT

1. [BLOCK] **“Skip” can finish without the inputs needed for a target.** The spec allows every field to be skipped and expects a skip-all run to reach Today (`docs/specs/phase-10-conversational-onboarding.md:183-185,539-540`), but target derivation rejects an incomplete profile (`lib/profile/derive.ts:109-116`; PR #241 `f743cfb:lib/profile/energy.ts:216-222`). Phase 9 also defines no target fallback (`docs/specs/phase-9-tenancy-blank-slate.md:557-560`). Require the six formula inputs before stage 9, or explicitly finish in `needs_profile` with no numeric targets; test both paths.

2. [BLOCK] **The goal classifier cannot directly populate the stored goal.** It returns `eat_better`, `accountability`, `manage_condition`, and `unclear` (`docs/specs/phase-10-conversational-onboarding.md:199-201`), while `Goal` accepts only `lose_fat | recomp | maintain | gain_muscle` (`lib/types.ts:38`). Rate presets are also goal-specific, not merely members of the column’s combined set (PR #241 `f743cfb:lib/profile/rate-goal.ts:11-30`). Define an explicit, confirmed mapping or a separate motivation field, and validate the rate against the chosen stored goal.

3. [BLOCK] **The completion RPC trusts a caller-supplied build across the authority boundary.** `complete_onboarding` is executable by `authenticated` and accepts `p_build jsonb`; the spec has it write profile fields, constraints, templates, and a computed target from that argument (`docs/specs/phase-10-conversational-onboarding.md:359-383`). A draft revision and template revision check do not prove that those values match confirmed draft fields or the summary the user approved. Store the validated build under the server-controlled draft, require an explicit summary-confirmed state, and have the RPC read and validate that state rather than accepting arbitrary write data from a direct caller. Bind the draft’s `thread_id` to the same owner, not just an arbitrary `coach_threads.id` (`:349-353`).

4. [BLOCK] **The proposed Eats write cannot create usable meal foods.** Stage 9 calls `set_food_membership` and says an unmatched name becomes a user food (`docs/specs/phase-10-conversational-onboarding.md:373-378`), but that RPC only finds existing user and catalog refs and writes preferences for those refs (`supabase/migrations/20261023090400_food_membership_v2.sql:25-55,93-115`). The phone’s meal projection is built from `user_foods`, including role and nutrients (`lib/store.ts:274-300`); composed meals need protein, carb, and fat picks (`lib/rotation.ts:171-194`). Specify transactional food/ref creation or catalog import with verified nutrients and role, and leave an unmatched food out of rotation until those facts exist.

5. [BLOCK] **The change feed description cannot represent the food writes.** It asks for one change row per changed entity, including `user_food_prefs`, and another for `target_profiles` (`docs/specs/phase-10-conversational-onboarding.md:377-382`). Preferences are keyed per `food_ref_id` (`lib/sync/keys.ts:10-12,30-35`), and one membership call can update many refs (`supabase/migrations/20261023090400_food_membership_v2.sql:38-56,107-115`). `write_target_revision` already emits its own target change row (`supabase/migrations/20261023091000_target_revision_transactions.sql:64-67`). Require a change row for every changed food/user-food row with its real key, and do not emit a duplicate target row; test a multi-ref name and the post-build pull.

6. [BLOCK] **Health disclosures can reach a model before the stated health gate runs.** Users may answer several stages in one message (`docs/specs/phase-10-conversational-onboarding.md:179-182`), but routing is marked health-context only at stage 6 or after the draft already contains a condition (`:432-437`). A user can disclose a condition in an earlier turn; Gemini extraction and Jev condition classification are specified before that draft state exists (`:197-205,422-428`). Gate the incoming text before either model, or treat all onboarding turns as health-context turns. Define the same refusal rule for Jev and test a condition disclosed in stage 1 or 4.

7. [BLOCK] **The measured body-fat path omits the measurement date.** The spec promises Katch-McArdle after a user confirms DEXA or InBody, but stage 9 writes `body_fat_source` without `body_fat_measured_on` (`docs/specs/phase-10-conversational-onboarding.md:291-293,370-372`). PR #241 requires that date and rejects a missing or older-than-180-day measurement (`f743cfb:supabase/migrations/20261028090000_body_fat_provenance.sql:9-13`; `f743cfb:lib/profile/energy.ts:79-93`). Capture and confirm the measurement date, persist it with the value and source, and test eligible, stale, and undated scans.

8. [BLOCK] **A Health receipt does not prove the backfill was saved.** The chat advances on `last_received_at` (`docs/specs/phase-10-conversational-onboarding.md:274-275`), but that timestamp is any ingest event receipt (`supabase/migrations/20261024093100_health_source_status.sql:3-7`). The ingest path records an “applied” event before applying samples, in a separate RPC; it can return `applied` with zero accepted and rejected samples, and a retry of the same payload is treated as duplicate (`lib/server/health-ingest.ts:93-114`; `supabase/migrations/20260925000000_phase5_health_ingest.sql:55-60`). Make event registration and sample application atomic or recoverable, and advance stage 3 only after verifying accepted metrics for that source and reporting partial rejection.

9. [BLOCK] **The published Shortcut has no defined route to the Preview branch.** Stage 2 sends a Preview-issued token to a shared Shortcut, while the phone test requires the samples on `p9-tenancy` (`docs/specs/phase-10-conversational-onboarding.md:260-275,522-525,545-550`). The existing Shortcut posts to a configured ingest URL (`docs/apple-health.md:37-39`); a production-hosted Shortcut cannot apply a Preview token to Preview. Specify and probe a Preview-specific Shortcut or a safe endpoint parameter that is persisted with the token. Verify the receiving source ID belongs to the same Preview account.

10. [BLOCK] **Turn concurrency has no state or transcript rule.** The draft has a `rev`, but the turn route is specified only as extract → judge → machine → persist (`docs/specs/phase-10-conversational-onboarding.md:349-353,418-428`). Two taps or two tabs can read the same stage, overwrite answers, and allocate the same next message sequence; the existing sequence helper reads `max(seq)+1` (`lib/server/coach-threads.ts:134-138`). Define per-user turn serialization, an expected draft revision, idempotent message IDs, and an atomic draft/message commit. Test concurrent turns, double taps, and a response lost after commit.

11. [FIX] **The name has no named consumer after it is saved.** Stage 1 captures `display_name`, and the migration adds it to the sync SQL (`docs/specs/phase-10-conversational-onboarding.md:168,408-412`), but the planned files omit the client profile mapping and coach context; today that mapping drops unknown columns (`lib/sync/user-settings.ts:74-119`), and the coach profile read selects a fixed set (`lib/server/coach-context.ts:70-93`). Specify where the name appears, how it is edited, and its client/server projections.

12. [FIX] **The Preview reset does not restore a fresh-account test state.** It clears the stamp, constraints, plan days, and template, but retains target history, Health samples, and existing Foods (`docs/specs/phase-10-conversational-onboarding.md:457-463`). The draft schema also has no `deleted_at` column despite “soft-deletes the draft” (`:349-353`). Define an actual reset state and mechanism, or use a new invited test account for each run; assert the second run has no inherited inputs or active target.

13. [FIX] **A backgrounded PWA can lose its only connection code.** The token is returned once (`app/api/health/tokens/route.ts:26-34`) and Phase 10 keeps it only in chat memory before switching to Shortcuts (`docs/specs/phase-10-conversational-onboarding.md:260-270`). If iOS reloads the PWA, the server draft can resume but Connect cannot repeat. Persist the pending source ID server-side, define token reissue/old-token revocation, and test a reload between Add Shortcut and Connect.

14. [FIX] **The displayed target date can overpromise the selected rate.** Phase 10 says it shows the date a preset reaches (`docs/specs/phase-10-conversational-onboarding.md:188-190`), while PR #241 caps the adjustment and may apply a macro minimum, yielding an effective rate different from the preset (`f743cfb:lib/profile/rate-goal.ts:57-71`). Calculate any estimate from the effective rate and current weight, label it an estimate, and suppress it when the goal amount or rate is unknown.

15. [FIX] **The new draft is absent from the backup inventory.** Phase 10 adds `onboarding_drafts` and promises closed-tab resumption (`docs/specs/phase-10-conversational-onboarding.md:349-353,408-413`); the backup job uses a fixed table list that will not include it (`app/api/jobs/backup/route.ts:30-48`). Add the table and a restore check, or state a deliberate expiration policy for incomplete drafts.

16. [FIX] **The deterministic end-to-end test still depends on a live judge.** `ONBOARDING_MODEL=fixture` is defined as scripted extraction, while turns also call Jev (`docs/specs/phase-10-conversational-onboarding.md:197-216,470-475,500-508`). Fixture or replay the judge in that Playwright run so the stage sequence and confirmations are reproducible; keep the separate live persona evaluation as the model gate.

17. [FIX] **An age answer is treated as a known birth year.** The skip-ahead example accepts “I’m 34” (`docs/specs/phase-10-conversational-onboarding.md:181-182`), but the stored profile and energy formula use `birthYear` (`lib/profile/energy.ts:3-8,21-28`), and the current form requires a birth year (`lib/profile/onboarding-state.ts:307-316`). Age alone permits two birth years depending on whether the birthday has passed. Ask for birth year or mark the conversion as inferred and confirm it before saving.
