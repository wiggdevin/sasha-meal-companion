1. [BLOCK] **The internal writer could remain callable by clients.** The spec gives `_write_target_revision_checked` “no grants,” but PostgreSQL grants function execution to `PUBLIC` by default. Existing migrations explicitly revoke it for private functions. M-a must revoke `EXECUTE` from `PUBLIC`, `anon`, and `authenticated` on the internal writer and `account_floor`, then test direct calls with an authenticated client. Evidence: [phase-12-coach-tools.md:98](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-12-coach-tools.md:98), [20260911000600_rpc.sql:19](/Users/zero-suminc./projects/clients/Sasha/meal-companion/supabase/migrations/20260911000600_rpc.sql:19).

2. [BLOCK] **The database floor lacks the existing weight-selection rules.** The spec says to use the “latest body-mass sample,” without an effective-date cutoff or unit conversion. The phone excludes samples after the target date; stored legacy samples can contain pounds, and the health reader converts them to kilograms. Define the SQL selection and conversion to match those rules, and test a future-dated sample and a legacy `lb` row against PR #241’s calculation. 3. [BLOCK] **The queued-target rule discards recoverable writes.** It removes a pending revision for *any* 4xx response. An expired session (`401`), client-upgrade gate (`426`), or rate limit (`429`) can therefore permanently discard a weigh-in retarget that would succeed after recovery. Retain or park those entries; remove only requests with a permanent, typed refusal, and test recovery after each status.
