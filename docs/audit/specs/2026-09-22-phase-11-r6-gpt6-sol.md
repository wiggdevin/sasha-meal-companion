1. [BLOCK] **Memory replacement is no longer atomic.** A contradiction must insert a replacement and mark the older row superseded; cap eviction adds another write. The revised route specifies ordinary `adminClient()` writes with no transaction, so a failure between writes can hide the old fact, leave two conflicting facts active, or exceed the cap ([spec:445](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-11-conversations-memory.md:445), [spec:484](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-11-conversations-memory.md:484), [spec:512](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-11-conversations-memory.md:512)). Keep the Jev checks in JavaScript, then commit the chosen row changes atomically in a restricted database function or equivalent transaction. Test failure after each write.

2. [BLOCK] **Soft-delete citation clearing lacks permission to run.** The proposed `coach_threads` trigger updates `coach_memories`, while authenticated users have no memory UPDATE policy and the thread DELETE route uses their RLS-scoped client ([spec:284](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-11-conversations-memory.md:284), [spec:329](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-11-conversations-memory.md:329), [route:62](/Users/zero-suminc./projects/clients/Sasha/meal-companion/app/api/coach/threads/[id]/route.ts:62)). A default invoker trigger cannot reliably clear those references. Specify a tightly scoped `SECURITY DEFINER` trigger with a fixed search path, and test both route deletion and direct owner PostgREST updates.

3. [BLOCK] **The new proposal field still has no client consumer.** The spec adds `memoryProposal` to the turn response and names a confirm component, but the current client sends the response only into `nextChatState()`, which retains `draft` and discards an unknown proposal field ([spec:393](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-11-conversations-memory.md:393), [CoachShell:238](/Users/zero-suminc./projects/clients/Sasha/meal-companion/components/coach/CoachShell.tsx:238), [chat-state:109](/Users/zero-suminc./projects/clients/Sasha/meal-companion/lib/coach/chat-state.ts:109)). Specify the reducer field or callback that opens and clears the Save/Not now card, including its behavior across remounts. Test tool result through a visible card and Save.

4. [BLOCK] **The proposed thread key cannot start a second chat after the first lazy creation.** `CoachScreen` keeps `resume.threadId` at `null`; its `onThreadSaved` callback writes only localStorage. The shell learns the new ID internally after the first turn, so setting the parent’s ID to `null` for “new chat” leaves the proposed `"new"` key unchanged and retains the old reducer state ([spec:232](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-11-conversations-memory.md:232), [CoachScreen:99](/Users/zero-suminc./projects/clients/Sasha/meal-companion/app/coach/CoachScreen.tsx:99), [CoachShell:232](/Users/zero-suminc./projects/clients/Sasha/meal-companion/components/coach/CoachShell.tsx:232)). Define parent selection state or a distinct new-chat generation key; test first chat → new chat and repeated new chats.

5. [FIX] **The dedupe judge still has no result contract or failure rule.** The spec calls for one batched judgment over 50 rows but does not define how it returns both a matched row and `same`/`updates`/`contradicts`/`unrelated`, or what a `null` Jev result does ([spec:479](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-11-conversations-memory.md:479), [spec:512](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-11-conversations-memory.md:512), [typesafe:239](/Users/zero-suminc./projects/clients/Sasha/meal-companion/lib/ai/typesafe.ts:239)). Define a validated matched-ID/verdict result and a no-write response when judgment fails.
