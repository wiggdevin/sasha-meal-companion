Verdict: DO NOT SHIP — 6 BLOCK, 5 FIX, 0 NIT

1. [BLOCK] The specified `remember_fact` provider shape does not fit the current wire contract. The spec adds named `memKind` and `text` fields with no expansion step (`docs/specs/phase-11-conversations-memory.md:317-333`), but `providerActionSchema` uses required compact fields to stay within the provider’s documented property limit (`lib/coach/actions.ts:237-270`). Put the values in the existing positional wire format, expand them before strict parsing, and test a provider response end to end.

2. [BLOCK] An unconfirmed proposal can enter the action and history paths as though it happened. The spec requires Save / Not now (`docs/specs/phase-11-conversations-memory.md:339-354`), while received actions become `pending` and are applied automatically (`lib/coach/chat-state.ts:109-120`; `components/coach/CoachShell.tsx:150-165`). Actions are also persisted and replayed into later history (`lib/server/coach-turn.ts:781-800`; `lib/coach/history.ts:93-97`). Define a separate proposed state that survives reload, never auto-applies, and is not rendered to the coach as a completed action after “Not now.”

3. [BLOCK] Undo is destructive for two specified dedupe outcomes. The token holds a memory ID and Undo deletes it (`docs/specs/phase-11-conversations-memory.md:325-333`), but `same`/`updates` changes an existing row and `contradicts` supersedes an older row (`:379-385`). Undo would delete the old row in the first case and leave it superseded in the second; cap eviction adds another irreversible effect (`:386-387`). Specify a correct inverse for each outcome, or remove Undo from memory saves and offer ordinary deletion.

4. [BLOCK] “Forget everything” can be followed by an already-started save. The spec explicitly accepts that race (`docs/specs/phase-11-conversations-memory.md:388-404`), and the client timeout does not stop server work (`lib/coach/apply-client.ts:122-153`). That is an unsafe outcome for a privacy control, even with the proposed warning. Fence saves against a per-account forget generation in a transaction, then test save-versus-forget and retry.

5. [BLOCK] The migration and ownership plan conflicts with the security migration already applied to production. Phase 11 requires a forged `coach_messages.user_id` to be silently corrected and proposes a mismatch backfill (`docs/specs/phase-11-conversations-memory.md:298-309,578-585`); the applied `20261103090100_same_owner_references.sql` trigger instead rejects that mismatch (`.claude/worktrees/agent-a539615ca814cfaf9/supabase/migrations/20261103090100_same_owner_references.sql:140-152,393-401`). The spec also names only `20261029090000` as its explicit timestamp floor (`docs/specs/phase-11-conversations-memory.md:558-566`). Preserve the deployed rejection rule, reconcile the triggers and tests, and require every new migration to sort after `20261103090100`.

6. [BLOCK] The medical-memory rule still has no usable decision boundary. The spec refuses a `null` Jev response but gives no threshold for a non-null response while guaranteeing that no medical memory is ever saved (`docs/specs/phase-11-conversations-memory.md:355-367,731-733`). `noul` returns a probability, not a Boolean (`lib/ai/typesafe.ts:67,124-126`; compare `lib/coach/verify.ts:55-57`). Define how uncertain scores are refused and replace the absolute guarantee with a testable one, or remove free-text memory if absolute exclusion is required. The Preview step also expects no save card for celiac, although the specified screen runs only after Save (`docs/specs/phase-11-conversations-memory.md:675-676`).

7. [FIX] Specify the actual thread-switch operation. “New chat” is described as clearing `threadId` (`docs/specs/phase-11-conversations-memory.md:201-206`), but `CoachChat` is keyed only by user and `CoachShell` initializes its reducer from `threadId` once (`app/coach/CoachScreen.tsx:117-119`; `components/coach/CoachShell.tsx:118-121`). Wire new/open/delete to a reducer reset or remount, cancel stale loads, and test switching while a turn is in flight.

8. [FIX] Define the dedupe judge’s response and failure path. The spec needs both a matched row and `same`/`updates`/`contradicts`/`unrelated`, but calls this one “choice-style” question and says nothing about a `null` result (`docs/specs/phase-11-conversations-memory.md:368-381`). `systemOne()` can return `null` on budget, timeout, and malformed output (`lib/ai/typesafe.ts:239-261,284-326`). Specify a bounded response schema and refuse or safely defer the write when judgment is unavailable.

9. [FIX] Give the recall verifier all evidence it is supposed to allow. The prompt permits claims found in injected context (`docs/specs/phase-11-conversations-memory.md:460-464`), but the proposed verifier receives only recall-result snippets (`:470-482`). Include bounded account-memory and current-thread context evidence, or limit this check explicitly to claims about other conversations.

10. [FIX] Update the Phase 9 device-cache dependency. Phase 11 says the current cache needs no change and need not wait for Phase 9 (`docs/specs/phase-11-conversations-memory.md:59-67,616-619`), while the unmerged Phase 9 device-isolation slice changes the cache API to require an account handle (`.claude/worktrees/agent-af9e42fc3664b612b/lib/coach-client.ts:85-93`). Plan Phase 11 against that merged API and test account switching there.

11. [FIX] Correct the purge-job implementation reference. The spec says the service-role purge iterates users “the way `media-sweep` already does” (`docs/specs/phase-11-conversations-memory.md:611-615`); `media-sweep` instead reads a global age-filtered batch (`app/api/jobs/media-sweep/route.ts:41-50`). Specify a bounded purge query and owner-scoped deletion using the thread’s verified `user_id`.
