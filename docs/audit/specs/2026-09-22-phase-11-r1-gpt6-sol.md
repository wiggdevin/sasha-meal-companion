# Audit: phase-11 round 1 (GPT-6 Sol, codex exec, xhigh, read-only)

Verdict: DO NOT SHIP — 9 BLOCK, 8 FIX, 0 NIT

1. **[BLOCK] The memory table bypasses its own safety rules.** The spec grants authenticated users insert and update access under an owner-only RLS policy (`docs/specs/phase-11-conversations-memory.md:271-275`), while medical screening applies only to the proposed model-write path (`:191-197`). A signed-in user can insert medical text or set `confirmed` directly. The proposed foreign keys also do not require `source_thread_id`, `source_message_id`, or `superseded_by` to belong to the memory’s user (`:158-166`). Restrict mutations to validated owner endpoints and enforce same-account references in the database; test direct Supabase writes as well as app routes.

2. **[BLOCK] The specified `remember` changes still discard every candidate.** The spec names the wire schemas and `planTurn()` (`docs/specs/phase-11-conversations-memory.md:172-185`), but `turnStepCandidate()` constructs a new final-step object and copies `memory` without copying `remember` (`lib/coach/wire.ts:100-130`). `TurnStep` also lacks the field (`lib/coach/turn.ts:21-28`). Specify both changes and test the complete provider-wire-to-persist path.

3. **[BLOCK] Registering `recall_conversations` does not make it runnable.** The spec adds a registry entry (`docs/specs/phase-11-conversations-memory.md:229-237`), but dispatch executes through `makeExecutors()`, a `Record<ToolName, Executor>` with no recall implementation (`lib/coach/executors.ts:78-114`); `defaultPorts()` supplies its I/O (`lib/server/coach-ports.ts:156-161`). Specify the owner-scoped search port, executor, result shape, and execution tests.

4. **[BLOCK] The proposed recall verifier cannot check its question.** The spec asks Jev whether a claim appears in retrieved results or injected context (`docs/specs/phase-11-conversations-memory.md:242-246`). `verifyReply()` sends only successful tool *names*, not their results or context (`lib/coach/verify.ts:19-21,50-56`), and the turn calls it only when `actions.length === 0` (`lib/server/coach-turn.ts:648-650`). Pass bounded evidence, run the recall check for every final reply, and define a fail-safe correction path when Jev is unavailable.

5. **[BLOCK] “Forget” is contradicted by the unchanged history paths.** Deleting a `coach_memories` row leaves the fact in its original messages and rolling thread summary (`lib/server/coach-threads.ts:116-131`; `lib/coach/history.ts:106-123`), and the new recall tool would search those messages. Yet the spec promises the fact is unused on the next turn (`docs/specs/phase-11-conversations-memory.md:254-258,320-325,358`). Define whether deletion suppresses that fact across history and recall, or narrow the promise and UI copy. Also reject new turns into soft-deleted threads: `DELETE` sets `deleted_at` (`app/api/coach/threads/[id]/route.ts:62-66`), but `resolveThread()` does not check it (`lib/server/coach-threads.ts:98-108`).

6. **[BLOCK] Deleting a replacement can resurrect a contradicted memory.** “Active” means `superseded_by is null`, while that FK uses `on delete set null` (`docs/specs/phase-11-conversations-memory.md:165-166,200-205`). If the user deletes the newer active fact, its superseded predecessor becomes active again. Use a durable superseded state independent of the replacement row, or delete the chain consistently; test edit, delete, and cap eviction.

7. **[BLOCK] Best-effort post-response work cannot support durable memory or immediate deletion.** `afterResponse()` can skip a task (`lib/server/after-response.ts:3-16`); after a reply is persisted, a retry returns `storedTurn()` before any proposed memory work is rescheduled (`lib/server/coach-turn.ts:233-235`). An in-flight task can also reinsert a memory after “Forget everything.” The spec schedules writes only through this wrapper (`docs/specs/phase-11-conversations-memory.md:207-211`). Persist an idempotent work intent with the turn, retry failures, and fence writes against a memory deletion generation.

8. **[BLOCK] The search migration has no document maintenance plan.** Slice 1 adds plain `tsvector` columns and GIN indexes (`docs/specs/phase-11-conversations-memory.md:150-154,333-335`), but plain columns require a backfill and updates on message insert and title rename. The cited catalog precedent explicitly has an import worker write its vector (`supabase/migrations/20260912090000_catalog_tables.sql:19-29`). Dedupe also calls for indexed search of `coach_memories` (`docs/specs/phase-11-conversations-memory.md:198-202`), while slice 1 names only two indexes. Specify all three maintained documents, historical backfills, and the authenticated search query or endpoint.

9. **[BLOCK] Stored prose can conflict with authoritative nutrition state.** `goal_context`, routines, and preferences are injected on every turn without a validity link to current profile, constraints, or target revision (`docs/specs/phase-11-conversations-memory.md:161-166,213-225`). The day context reads revision-backed targets (`lib/server/day-context.ts:181-203`; `lib/server/coach-context.ts:210-222`). A remembered calorie goal or food rule can remain after Settings changes it. Exclude authoritative numbers and rules from free-text memory, or version and invalidate those memories; require current server state to win in prompt and tests.

10. **[FIX] Correct the device-cache claim before implementing its proposed change.** Although `cacheKey()` takes a single string (`lib/coach-client.ts:79-81`), its actual read and write callers already pass `${userId}:${threadId}` (`components/coach/CoachShell.tsx:110-115,202-205`). Following the spec literally (`docs/specs/phase-11-conversations-memory.md:285-290`) would double-prefix keys. Document the current behavior, test account switching, and distinguish transcript keys from `smc:coach:current:<userId>` (`app/coach/CoachScreen.tsx:16-17`).

11. **[FIX] Clear citations at soft delete, including the message citation.** Decision 1 says a deleted thread immediately loses its citation (`docs/specs/phase-11-conversations-memory.md:110-113`), but `on delete set null` fires only at hard purge, 30 days after `deleted_at` (`:145-149,162-164`). Clear or hide both source references when soft-deleting, and test the 30-day interval.

12. **[FIX] Register and test the daily purge as a scheduled job.** The slices specify a route but no `vercel.json` entry (`docs/specs/phase-11-conversations-memory.md:343-346`); the current schedule lists only six other jobs (`vercel.json:2-9`). Add the cron entry. Preview step 3 also cannot prove a 30-day cutoff by invoking the job immediately after deletion (`docs/specs/phase-11-conversations-memory.md:313-316`); use aged preview fixtures or an injected clock.

13. **[FIX] Expose the new export to the user.** Adding `memories` to the route’s `SOURCES` map (`docs/specs/phase-11-conversations-memory.md:259-261`) does not add it to the Settings export control, which currently offers only meals and progress (`components/ExportCard.tsx:5-9,58-70`). Specify the download control and verify deleted rows are absent.

14. **[FIX] Make the context cap enforceable.** The spec says an untrimmed 800-character memory field stays inside 2,500 tokens (`docs/specs/phase-11-conversations-memory.md:213-222,296-297`). `renderCoachContext()` has a finite shrink list and returns its result even if it still exceeds the cap (`lib/server/coach-context.ts:249-267`). Define a final bounded fallback and test an already-near-cap context with memory added.

15. **[FIX] Test contradictions that lexical search misses.** The five closest full-text matches are the *only* rows sent to the dedupe judge (`docs/specs/phase-11-conversations-memory.md:198-202`). “I’m vegetarian” and “I eat meat now” need not share search terms, so both can remain active. At the stated 200-row cap (`:203-206`), add a broader candidate strategy and explicit reversal fixtures.

16. **[FIX] Define offline behavior for memory controls.** The spec promises immediate Edit, Delete, and “Forget everything” (`docs/specs/phase-11-conversations-memory.md:250-258`) but specifies neither an account-scoped outbox operation nor an online-only error state. Coach turns themselves are live and not queued (`lib/coach-client.ts:3-5`). State whether these controls require a connection or queue durable, user-bound operations, and test reconnect and account switching.

17. **[FIX] Pin down first-message titles for “new chat.”** The existing `POST /api/coach/threads` can create an untitled thread (`app/api/coach/threads/route.ts:37-46`), while `persist()` derives a title only when the turn has no existing thread ID (`lib/server/coach-threads.ts:159-167`). The spec promises the unchanged first-message title mechanism alongside a new-chat control (`docs/specs/phase-11-conversations-memory.md:138-144`). Specify whether new chat waits to create a thread until the first send or assigns that title on the first turn of a pre-created thread.
