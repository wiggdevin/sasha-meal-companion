## Verdict: DO NOT SHIP

Direct Gemini Live is a reasonable **spike** for this PWA. The spec is not ready to ship because its safety parity, tool provenance, and spend caps depend on guarantees the proposed client connection cannot provide.

1. **[BLOCK] The 250 ms guard cannot prevent unsafe speech.** [§6.2](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:319>) assumes transcription leads audio. Google says there is **no guaranteed ordering** between output transcription and audio. A transcript match and later correction cannot undo an audible allergen recommendation. Use checked text → TTS for food and health advice, or explicitly weaken the “same rules as typed” requirement. A 30-prompt, zero-violation test does not prove that guarantee. [Google Live API reference](https://ai.google.dev/api/live)

2. **[BLOCK] The bridge cannot prove a tool call came from Gemini.** [§4.2](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:229>) checks the user, session, and replayed `callId`; all tool fields still arrive from the browser. `validateToolCall` validates a name and arguments, not their origin ([dispatch.ts:30](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/coach/dispatch.ts:30>)). A client can invent calls and policy records. Keep the bridge read-only with separately authorized writes, or put the model connection and tool events in a trusted worker.

3. **[BLOCK] Spoken medical deflection and action claims occur too late.** [§5](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:304>) classifies input and verifies output transcripts after audio can start. The typed path deflects *before* its model call and checks claims before render ([coach-turn.ts:245](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/server/coach-turn.ts:245>), [coach-turn.ts:648](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/server/coach-turn.ts:648>)). Route these turns through checked mode before speech.

4. **[BLOCK] The cost cap is not a cap.** [§9](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:402>) records `min(reported cost, wall-time bound)` **after** the session. A client can report zero; concurrent sessions can exceed the minute limit; a lost client need not close one. The existing spend check also fails open on database errors ([spend.ts:31](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/ai/spend.ts:31>)). Reserve minutes atomically at mint, enforce a server-side deadline and concurrency limit, and reconcile against provider billing. Google bills retained context again per turn and charges for transcription, so `$0.035 × wall minutes` is not a hard upper bound. [Google billing guidance](https://ai.google.dev/gemini-api/docs/live-api/best-practices)

5. **[BLOCK] “Server truth” is overstated.** [§4.4](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:284>) trusts client transcripts, turn numbers, action IDs, and usage. Bridge records can prove what it returned, not what Gemini said or what the phone applied. [apply-client.ts:106](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/coach/apply-client.ts:106>) tracks application on the phone; [persist](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/server/coach-threads.ts:159>) inserts message rows separately, while `nextSeq` reads then increments. Mark direct-session transcripts as client reported, add an idempotent transactional turn write, and record action settlement through a server acknowledgment.

6. **[BLOCK] D2 text can reach a D1-only verifier.** [§9](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:386>) calls the output transcript D1 for Jev. `verifyReply` sends the full reply and action summaries to TypeSafe ([verify.ts:33](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/coach/verify.ts:33>)); a spoken answer can contain health context. Disable that call for voice until a D2-safe projection or attested D2 route exists. The Phase 13 call registry and attestation gate cited by the spec are not in this checkout.

7. **[FIX] Policy filtering must cover more than search hits.** [§4.2](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:247>) says only the user can put blocked food in model context. The existing context includes Avoid names ([coach-context.ts:239](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/server/coach-context.ts:239>)); `get_constraints` exposes rules ([registry.ts:124](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/coach/registry.ts:124>)). `checkReply` only checks text against foods already in its evidence map ([reply-check.ts:71](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/coach/reply-check.ts:71>)). Audit every model-facing context and tool result; do not describe this checker as an open-vocabulary spoken-food check.

8. **[FIX] Reconsider LiveKit against the actual requirement.** [§3](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:119>) assigns it an unmeasured 50–150 ms penalty and little value. For *this* app, a trusted agent worker could own tool events, accounting, and WebRTC transport; it adds a D2 processor, deployment, and cost, and it **does not** solve unchecked native speech or iOS backgrounding. Keep direct Gemini for slice 0, but make the production decision after the phone and security gates. Pipecat has the same worker tradeoff; a chained path preserves the typed checks at higher latency. OpenAI Realtime offers WebRTC and server controls, but introduces another D2 provider. [LiveKit integration](https://docs.livekit.io/agents/integrations/google/), [LiveKit pricing](https://livekit.com/pricing), [OpenAI server controls](https://developers.openai.com/api/docs/guides/voice-server-controls)

9. **[FIX] iPhone session ending is only best effort.** [§6.3](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:339>) promises a clean persist on `visibilitychange: hidden`; a suspended page may not finish the POST, leaving “Your words are saved” false. Journal completed turns while foregrounded, stop mic and playback immediately on hide, and restore from server state on the next tap. Test worklet availability, audio interruptions, Bluetooth route changes, wake-lock release, and AEC double-talk on the installed PWA. Wake Lock support in Home Screen apps required an iOS fix; it is not a session guarantee. [WebKit issue](https://bugs.webkit.org/show_bug.cgi?id=254545), [page lifecycle guidance](https://developer.mozilla.org/en-US/docs/Web/API/Document/visibilitychange_event)

10. **[FIX] Resumption needs a failure contract.** [§4.1](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:225>) proposes raising `uses` to 3 if reconnect fails. Google documents `uses: 1` resumption, but also says handles can be non-resumable during generation or function calls; older provider reports found token and context failures. Test the pinned SDK and model, require a valid `resumable` handle, and fall back to a new session with explicit context recovery. Do not increase uses as an assumed fix. [Google API reference](https://ai.google.dev/api/live), [reported token issue](https://discuss.ai.google.dev/t/ephemeral-token-resumption-consumes-uses-even-with-uses-1-live-api-v1alpha/118180)

11. **[FIX] The latency gate cannot yet measure its claims.** [§7](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:355>) reuses `voice`, which already means capture in [timing.ts:15](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/timing.ts:15>); its proposed steps are absent from the client and database allowlist ([migration:6](</Users/zero-suminc./projects/clients/Sasha/mc-voice/supabase/migrations/20261023092000_client_timings_attach_step.sql:6>)). Add a distinct `coach-voice` path, the migration, and paired onset/audio/playback timestamps. Measure first **useful** answer separately from “Checking your plan.” Twenty sessions are too few to establish a stable p95, especially with VAD silence and the added playout delay.

12. **[FIX] Finish the release and accessibility gates.** [§8–10](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:374>) lacks a migration order, concurrent-mint tests, a lost-client reconciliation test, and an active-session rollback: turning off mint leaves an issued token usable until expiry. Add those gates, plus captions, VoiceOver announcements, a non-audio error path, and an accessible way to review and Undo cards. The proposed checked-mode fallback also depends on live dictation planned **after** checked mode, in slice 6.
