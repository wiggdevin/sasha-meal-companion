1. [BLOCK] **A checked revision can persist a lower floor.** The spec checks the stricter stored-profile floor but does not require that floor to be written into the revision ([spec:95–99](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-12-coach-tools.md:95)). On PR #241, derivation takes the floor from the request profile (`origin/feat/tdee-rate-goals:lib/profile/derive.ts:124-130`), and `writeDerivedTargets` persists it (`origin/feat/tdee-rate-goals:lib/server/targets.ts:116-120`). A forged lower weight with a high enough pin can pass the check, leaving a lower active floor; the existing authored path then reads that floor (`origin/feat/tdee-rate-goals:lib/server/targets.ts:238-242`). Persist the stricter checked floor and use the stored-profile check for authored writes. Test this two-request sequence.

2. [BLOCK] **The floor check can race a profile change.** The spec places the check before the target RPC and requires no migration ([spec:110–117](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-12-coach-tools.md:110), [spec:249–253](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-12-coach-tools.md:249)). The target writer locks `userId` ([SQL:19](/Users/zero-suminc./projects/clients/Sasha/meal-companion/supabase/migrations/20261023091000_target_revision_transactions.sql:19)); settings sync uses a different lock ([SQL:436](/Users/zero-suminc./projects/clients/Sasha/meal-companion/supabase/migrations/20260919090300_phase3_sync_entities.sql:436)). Another device can raise the stored floor after the route reads it and before the target write commits. Put the profile-version/floor check in a transaction coordinated with settings writes, or narrow the claimed guarantee and specify a safe conflict response.

3. [BLOCK] **Undo of a refused weigh-in target can fail after changing the weight back.** The new `targets_refused` result retains `previousTargetRevisionId` ([spec:152–157](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-12-coach-tools.md:152)). The current coach token copies that ID ([apply-body.ts:77–84](/Users/zero-suminc./projects/clients/Sasha/meal-companion/lib/coach/apply-body.ts:77)), and Undo restores it *after* undoing the weight ([apply-body.ts:89–132](/Users/zero-suminc./projects/clients/Sasha/meal-companion/lib/coach/apply-body.ts:89)). Since the refused target write changed no revision, that restore is unnecessary and may itself fail the new floor check. Mark the token as having no target change and skip target restore; test Undo with a prior revision below the current floor.

4. [FIX] **A queued floor refusal has no notice consumer.** The spec says to announce “Targets not changed” through `announceQueued` ([spec:158–161](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-12-coach-tools.md:158)). That function emits an event with no payload ([outbox.ts:65–68](/Users/zero-suminc./projects/clients/Sasha/meal-companion/lib/sync/outbox.ts:65)); its listener only schedules sync ([SyncBootstrap.tsx:72–83](/Users/zero-suminc./projects/clients/Sasha/meal-companion/components/SyncBootstrap.tsx:72)). Specify an account-scoped notice that survives a background drain or reload and is cleared after display.

5. [FIX] **The old-client gate filters actions but leaves their claims visible.** The spec drops `update_setting` actions from responses to older builds ([spec:199–201](/Users/zero-suminc./projects/clients/Sasha/meal-companion/docs/specs/phase-12-coach-tools.md:199)). Replay returns stored assistant content separately from actions ([coach-threads.ts:73–85](/Users/zero-suminc./projects/clients/Sasha/meal-companion/lib/server/coach-threads.ts:73)), and thread history also returns that content ([route.ts:41–49](/Users/zero-suminc./projects/clients/Sasha/meal-companion/app/api/coach/threads/[id]/route.ts:41)). An old build could show “switching to kilograms” without an applicable card. Specify neutral copy for capability-filtered replay and history, with an old-build test.
