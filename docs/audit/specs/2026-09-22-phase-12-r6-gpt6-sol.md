1. [BLOCK] **Research can still produce a write-capable draft.** The isolation rule drops actions and rejects `effect: "propose"` tools (`docs/specs/phase-12-coach-tools.md:191-200`), but Phase 11 replaced `remember_fact` with `propose_memory`, an `effect: "draft"` tool whose card can save a memory (`docs/specs/phase-11-conversations-memory.md:363-405`). The existing `draft_log_entry` is also a draft, and the turn loop carries drafts into its response (`lib/server/coach-turn.ts:735-755`). Suppress all write-capable drafts and cards on a research turn, and bind memory confirmation to a server-verified non-research origin. Replace the nonexistent `remember_fact` route test with a `propose_memory` draft and confirmation test.

2. [BLOCK] **The specified settings writer does not sync schedule changes.** Group A promises synced, undoable `slotTimes.<slot>` and `shiftMinutes` changes through `writeSettings` plus sync (`docs/specs/phase-12-coach-tools.md:121-126`). `writeSettings` only saves the phone store, while `syncProfileSettings` omits `slot_times` and `shift_minutes` from its payload (`lib/coach/apply-profile.ts:27-48`; `lib/sync/user-settings.ts:97-119`). Specify a writer and Undo that queue those exact server fields through the settings intent path. Test apply, sync, reload on another device, and Undo for both keys.

3. [FIX] **The retained `get_plan` read has the pending-edit problem cited for cutting `get_calendar`.** The spec keeps `get_plan` (`docs/specs/phase-12-coach-tools.md:148-153`). A plan edit enters the phone’s outbox first (`lib/plan-day-client.ts:103-141`), while `get_plan` reads the server plan and the coach request carries no pending plan edit (`lib/server/coach-ports.ts:245-249`; `lib/coach/types.ts:29-40`). Include this phone’s pending edit or label the answer as a server snapshot when that date has an unsynced change.

4. [FIX] **The tenancy section incorrectly says tools read through the caller’s RLS client.** `docs/specs/phase-12-coach-tools.md:266-273` names only the usage counter and `ai_calls` as service-role uses. Existing `get_plan` and `get_entries` call `buildDayContext` with the admin client (`lib/server/coach-ports.ts:245-253`), which reads `plan_days` through that client (`lib/server/day-context.ts:176-185`). Document those privileged reads and require explicit `userId` scoping and cross-user tests for every such port.

5. [FIX] **The CSV truncation test uses the wrong unit.** The spec calls the 5,000 limit “rows” and tests more than 5,000 meal rows (`docs/specs/phase-12-coach-tools.md:164-168,305`). `streamMeals` limits **log entries**, then expands each entry into item rows (`lib/server/export.ts:175-205`). A fixture with 5,001 item rows across fewer entries will not truncate. Test more than 5,000 entries, and separately test that a complete export may contain more than 5,000 item rows.
