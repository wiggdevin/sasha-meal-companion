### New findings

1. **[BLOCK] A partial `reply` is not a validated final step.** Rev 2 puts `reply` first and emits sentences while the JSON is growing ([spec:247](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:247>)). The current wire schema puts `kind`, `actions`, and `suggestions` before `text`, then validates the **complete** object ([wire.ts:47](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/coach/wire.ts:47>), [wire.ts:119](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/coach/wire.ts:119>)). The typed path also sanitises the completed reply; that sanitiser can cut or replace earlier text ([turn.ts:264](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/coach/turn.ts:264>)). Google supports partial JSON streaming, but final schema validity is known only when the object completes. [Google structured output documentation](https://ai.google.dev/gemini-api/docs/generate-content/structured-output). **Fix:** validate the full final step, including actions and final sanitised text, before TTS. Treat early text as an untrusted preview; measure whether streaming still earns its complexity.

2. **[BLOCK] Sentence checks do not preserve whole-reply parity.** The typed `checkReply` can replace the *whole* response and clear its actions when a later sentence names blocked evidence ([reply-check.ts:71](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/coach/reply-check.ts:71>)). Rev 2 may already have spoken earlier sentences and sent cards when sentence 2 fails ([spec:251](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:251>), [spec:275](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:275>)). Its term list also cannot prove an open-vocabulary food recommendation safe; `checkReply` examines named suggestions and known evidence, not every food name. **Fix:** run final whole-turn checks before speech and card release; use the term screen as an additional guard, with explicit limits and tests for aliases, inflections, brands, negation, and policy explanations.

3. **[BLOCK] A matching card does not prove a completed action.** `claimsAction` is a narrow regex ([actions.ts:65](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/coach/actions.ts:65>)); Jev checks broader unlisted claims only at the end ([verify.ts:37](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/coach/verify.ts:37>)). The phone applies cards *after* the server returns them, and application can fail ([apply-client.ts:106](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/coach/apply-client.ts:106>)). Thus a card cannot justify speaking “saved,” and a later correction cannot retract it ([spec:262](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:262>)). **Fix:** speak pending language until the phone acknowledges application; verify the complete reply before speech, or remove completion claims from spoken output.

4. **[BLOCK] Interrupt persistence is not transactional.** The spec says abort stops further work yet the server finishes persistence, and says abort writes nothing despite allowing cards before speech ends ([spec:277](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:277>), [spec:283](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:283>)). Current `nextSeq` reads then increments; `persist` inserts user and assistant rows separately ([coach-threads.ts:134](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/server/coach-threads.ts:134>), [coach-threads.ts:159](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/server/coach-threads.ts:159>)). Retrying a sequence conflict can leave an orphan user row; a second request can race the first server invocation even if the client aborted its stream. Vercel requires cancellation to be configured and post-cancellation work to be scheduled explicitly. [Vercel cancellation documentation](https://vercel.com/docs/functions/functions-api-reference). **Fix:** reserve a turn row at acceptance, finalize both messages and sequence atomically in an RPC, give each turn a durable pending/completed/interrupted state, and test disconnect, retry, and two-device ordering.

5. **[BLOCK] The 60-second route budget contradicts the code and client deadline.** Rev 2 assumes a “#254 30 s loop” plus TTS ([spec:292](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:292>)). This checkout sets `TURN_LIMITS.wallClockMs` to **75 seconds** ([turn.ts:60](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/coach/turn.ts:60>)); the current phone uses **40 seconds** ([fetch-with-deadline.ts:31](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/fetch-with-deadline.ts:31>)). A 45-second voice deadline, grounding, several TTS calls, and persistence cannot be asserted to fit a 60-second function. Streamed waiting counts toward Vercel duration. [Vercel duration documentation](https://vercel.com/docs/functions/configuring-functions/duration). **Fix:** give voice one measured server deadline covering model, TTS, and commit, with reserved cleanup time; set a matching client deadline and test a slow multi-tool turn.

6. **[FIX] Limits can be bypassed and the claimed $2 cap is not hard.** The voice route accepts client text plus `earsId`, but the spec does not require an active, user-owned ears reservation for each turn ([spec:233](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:233>)). A direct caller could use the higher 40/150 voice limits without voice. Counting persisted messages also misses concurrent and failed provider calls. Current spend reads and `ai_calls` writes fail open, with only an in-process lock ([spend.ts:31](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/ai/spend.ts:31>), [adapter.ts:321](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/ai/adapter.ts:321>), [adapter.ts:408](</Users/zero-suminc./projects/clients/Sasha/mc-voice/lib/ai/adapter.ts:408>)). **Fix:** bind voice turns to an active ears row, atomically reserve turn and estimated spend across instances, charge failures, and reconcile actual usage. Define whether typed and voice share an overall turn ceiling.

7. **[FIX] Ears renewal conflicts with concurrency one.** A mint refuses an existing open session, while rolling renewal calls the same route *before* expiry and reserves another five minutes ([spec:202](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:202>), [spec:220](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:220>)). **Fix:** specify an atomic rotate operation that closes the prior reservation and mints its successor, including a lost-client expiry rule and a provider-mint-failure refund. Google describes `expireTime` as the point after which messages are rejected; that supports a send bound, not the spec’s claim that an open socket necessarily “dies” then. [Google ephemeral token documentation](https://ai.google.dev/gemini-api/docs/live-api/ephemeral-tokens), [Live API reference](https://ai.google.dev/api/live).

8. **[FIX] Recovery and timing gates need observable states.** On iOS hide, rev 2 leaves a turn running, then rereads the thread; the existing thread GET returns committed messages only, so an in-flight or lost turn is invisible ([spec:317](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:317>), [thread route:41](</Users/zero-suminc./projects/clients/Sasha/mc-voice/app/api/coach/threads/[id]/route.ts:41>)). The proposed timing steps omit speech onset, so “word spoken → interim” and the 200 ms barge-in gate lack a defined start mark ([spec:370](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:370>)). **Fix:** expose pending turn status on restore, reconcile cards and their applied state, record audio/VAD onset and actual playback onset, and separate acknowledgement playback from first useful answer. Test lock, network loss, Bluetooth change, and rollback during an active turn.

9. **[NIT] The ack copy can overclaim.** “Looking at your plan” is sent on a timer even if the turn is still at a gate or cannot load the plan ([spec:279](</Users/zero-suminc./projects/clients/Sasha/mc-voice/docs/specs/phase-14-voice-agent.md:279>)). **Fix:** use neutral clips such as “One moment,” and preload them so the 700 ms *send* timer can be measured against actual playback.
