1. [BLOCK] Slice 1 can delete an unsent meal. [The cleanup rule](docs/plans/2026-09-22-phase-9-tenancy/slice-1-device-state-isolation.md:1396) deletes an account DB when its outbox and drafts are empty. A log commit first saves its retry request in the DB’s `pending_log_entries` meta key, then queues the op ([pending.ts](/Users/zero-suminc./projects/clients/Sasha/meal-companion/lib/log/pending.ts:30), [log-commit-client.ts](/Users/zero-suminc./projects/clients/Sasha/meal-companion/lib/log-commit-client.ts:245)). A switch in that interval can erase the only retry record. Count pending log records and other durable pending work before deletion; fail closed if the DB cannot be read, and test this exact switch.

2. [BLOCK] An A response can be cached as B’s health or expenditure data. [`accountFetch`](docs/plans/2026-09-22-phase-9-tenancy/slice-1-device-state-isolation.md:1022) checks the handle before sending, while the [storage rule](docs/plans/2026-09-22-phase-9-tenancy/slice-1-device-state-isolation.md:644) uses the account bound *when the cache helper runs*. The current health path writes its cache after awaiting the response ([health-client.ts](/Users/zero-suminc./projects/clients/Sasha/meal-companion/lib/health-client.ts:91)); expenditure does the same ([estimator-client.ts](/Users/zero-suminc./projects/clients/Sasha/meal-companion/lib/estimator-client.ts:61)). Pass the initiating handle through response parsing and every cache or store write, assert it after awaits, and test an A response arriving after B binds.

3. [BLOCK] The server change breaks old tabs for existing accounts. [Slice 1](docs/plans/2026-09-22-phase-9-tenancy/slice-1-device-state-isolation.md:1209) makes `/api/sync/ops` return `account_unbound` for every op without `user_id`; the [plan explicitly says older builds lack it](docs/plans/2026-09-22-phase-9-tenancy/slice-1-device-state-isolation.md:1108). That contradicts [rev 4’s promise that Sasha’s old tabs keep working](docs/specs/phase-9-tenancy-blank-slate.md:441). Opening her app online once does not prove every old tab or offline device has drained. Define and test a safe old-client cutover and an owner-proved recovery path before deploying this route.

4. [BLOCK] Sasha’s legacy eaten ticks have no completed migration path. [Adoption holds the entire old store blob](docs/plans/2026-09-22-phase-9-tenancy/slice-1-device-state-isolation.md:1264), while the new store reads an account key ([slice 1](docs/plans/2026-09-22-phase-9-tenancy/slice-1-device-state-isolation.md:644)). The current tick migration reads `loadStore().days` and writes its marker only after acknowledgement ([plan-days.ts](/Users/zero-suminc./projects/clients/Sasha/meal-companion/lib/sync/plan-days.ts:20)). If that migration has not finished before upgrade, the held ticks never enter the new path. Require proof that Sasha’s marker and queue have settled, or add an owner-proved import before switching stores.

5. [BLOCK] M2’s rollback can fail after the feature is used. That violates the [ready-after-adoption contract](docs/specs/phase-9-tenancy-blank-slate.md:174) and permits sync after a partial copy. Mark ready only after successful adoption; show or retain a retryable failure state for other errors.
